요구사항: $ARGUMENTS

`CLAUDE.md`, `MEMORY.md`, 기존 `SPEC_*.md`를 읽고 SPEC 초안을 만든다. 코드는 만들지 않는다.

## 절차
1. 기존 SPEC과 `MEMORY.md`에서 다음 번호(NN)와 `depends_on`을 정한다.
2. 요구사항을 아래 구조로 정리한다. 구조는 `SPEC_00_PROJECT.md`와 같게 유지한다.
   - front matter: `id`, `title`, `depends_on`, `max_iterations`(기본 3)
   - 1. 목표 (이번 단계에서 하는 일, 하지 않는 일 한 줄씩)
   - 2. 기술과 파일 구조 (`CLAUDE.md` 기술 제약과 충돌하지 않게)
   - 3. 화면 정의
   - 4. 상태와 공개 함수 (`globalThis.TetrisGame` 기준)
   - 5. 범위 밖
   - 6. 완료 조건 (체크박스)
   - 7. 자동 검증
   - 8. 수동 검증 (사람이 하는 단계별 절차)
   - 9. 안전과 정지 조건
3. `SPEC_NN_이름.draft.md`로 저장하고 요약을 보여준다. 기존 SPEC 파일은 수정하지 않는다.

## 작성 규칙
- 완료 조건은 관찰 가능하고 예/아니오로 판정되게 쓴다. "적절히", "자연스럽게" 같은 표현은 쓰지 않는다.
- 완료 조건마다 자동 검증으로 확인할지, 사람이 확인할지 드러나게 한다.
- 요구사항에 없거나 모호한 결정은 추측하지 말고 해당 위치에 `[사람 확인 필요]`로 남기고, 끝에 질문 목록으로 모은다.
- 한 SPEC은 한 번의 반복 실행(최대 3회)으로 끝낼 수 있는 크기로 자른다. 크면 나눠서 제안한다.
- 범위 밖에는 다음 SPEC에서 다룰 항목을 명시한다.

## 끝에 보고
- 저장한 파일 경로
- `[사람 확인 필요]` 목록
- 승인 방법: 사람이 검토한 뒤 `.draft`를 뗀 파일명으로 바꾸라고 안내한다. 에이전트가 스스로 승인하지 않는다.
