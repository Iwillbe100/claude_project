# CLAUDE.md — TETRIS LOOP 워크숍 하네스

이 프로젝트는 SPEC 문서 한 장씩을 반복 실행해 브라우저 테트리스를 만드는 워크숍이다.
작업 전 항상 이 파일과 `MEMORY.md`를 읽는다.

## 1. 기술 제약
- HTML5, CSS, 브라우저 기본 JavaScript만 사용한다.
- 금지: 프레임워크, 번들러, 패키지 매니저, 외부 라이브러리, 설정 파일, 개발 서버, 빌드 단계.
- `index.html`은 `style.css`, `game.js`, `main.js`를 직접 불러온다. `game.js`가 `main.js`보다 먼저이며 두 스크립트 모두 `defer`를 쓴다.
- `test.html`은 `game.js`, `test.js`를 직접 불러온다.
- 공개 API는 `globalThis.TetrisGame` 하나로 노출한다.
- 파일은 브라우저에서 직접 열어(file://) 동작해야 한다.

## 2. 폴더 경계
- 제품 코드는 `tetris-loop-workshop/` 안에만 둔다.
- 쓰기 가능: `tetris-loop-workshop/`, `MEMORY.md`, `.claude/`, 실행 보고, SPEC 초안(`SPEC_*.draft.md`).
- 읽기 전용: 승인된 `SPEC_*.md`. 수정은 사람이 하거나 `/spec-new`로 만든 초안을 사람이 승인해서만 한다.
- 프로젝트 폴더(`C:\claude_project\loop`) 밖의 파일은 만들거나 수정하지 않는다.
- `slides-export.pdf` 등 기존 자료는 수정하지 않는다.

## 3. 정지 조건 (하나라도 해당하면 즉시 중단하고 보고)
- 같은 실패가 2회 반복됨.
- SPEC의 `max_iterations`(없으면 3)회를 실행해도 완료하지 못함.
- SPEC에 없는 화면·기술 결정이 필요함 → 추측하지 말고 `[사람 확인 필요]`로 보고.
- 외부 배포 또는 유료 서비스가 필요함.
- SPEC의 "범위 밖" 항목을 구현해야 하는 상황.
- 금지된 기술(위 1번)을 써야만 통과하는 상황.

중단할 때는 원인, 시도한 것, 필요한 사람의 결정을 보고하고 `MEMORY.md`에 기록한다.

## 4. 완료 선언의 근거 규칙
- 완료 조건의 체크박스마다 근거를 하나씩 붙인다. 근거 없는 항목은 통과로 쓰지 않는다.
- 근거 종류를 구분해서 표기한다.
  - `[자동]` 테스트 러너 결과 등 실행해서 얻은 출력.
  - `[에이전트 확인]` 파일 내용, 스크립트 순서, grep 등 에이전트가 직접 확인한 정적 점검.
  - `[사람 확인 필요]` 브라우저 화면, 콘솔 오류, 390px 가로 스크롤 등 에이전트가 직접 볼 수 없는 항목.
- 에이전트가 직접 보지 못한 항목을 "통과"라고 쓰지 않는다. 사람 확인이 남아 있으면 상태는 "완료"가 아니라 "사람 확인 대기"다.
- 사람이 프롬프트로 전달한 확인 결과는 `MEMORY.md`에 `출처: 사람`으로 기록하고, 에이전트 결과와 충돌하면 사람 결과를 따른다.
- 테스트를 삭제·약화·우회해서 통과시키지 않는다. 실행하지 않은 검증을 실행했다고 쓰지 않는다.

## 5. 작업 방식
- 한 번에 SPEC 한 장만 실행한다. 다른 SPEC의 범위를 미리 구현하지 않는다.
- 변경은 해당 SPEC의 목표와 완료 조건에 필요한 만큼만 한다.
- `MEMORY.md`는 에이전트만 수정한다. 사용자는 프롬프트로 결과를 전달하고, 에이전트가 기록한다.
- 명령: `/spec-new`(요구사항 → SPEC 초안), `/spec-run`(SPEC 실행·검증·보고).
