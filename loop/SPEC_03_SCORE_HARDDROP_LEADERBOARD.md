# SPEC 03 — 점수, 하드 드롭, 로컬 리더보드

> 근거: 사람이 준 워크숍 순서("SPEC 03 점수, 하드 드롭, 로컬 리더보드 저장 규칙까지 검증 가능한 스펙")와 `slides-export.pdf` 59~61쪽에서 읽을 수 있는 숫자·영문(100/300/500/800, 1, Space 2, trim 2~10, `tetris-loop.leaderboard.v1`, `id name score clearedLines playedAt`, TOP 10, playedAt, 11→10, JSON, localStorage). 슬라이드의 한글 설명은 판독하지 못해 해석이 필요한 곳은 `[사람 확인 필요]`로 남긴다.

## 1. 목표

- 하는 일: 줄 제거와 드롭으로 점수를 얻고, `Space`로 하드 드롭하며, 게임 오버 뒤 이름을 넣어 이 브라우저에 TOP 10 기록을 저장하고 보여준다.
- 하지 않는 일: 레벨, 속도 증가, 레벨 점수 배수, 다음 블록 미리보기, 일시정지, 서버 저장·온라인 순위는 구현하지 않는다.

## 2. 기술과 파일 구조

- SPEC_00의 기술 제약을 따른다. 저장은 브라우저 기본 `localStorage`만 쓴다(외부 서비스 없음).
- 새 파일을 추가하지 않는다. 다음 파일만 수정한다.
  - `game.js`: 점수 규칙, 하드 드롭, 이름 검증, 리더보드 목록 처리(정렬·자르기·파싱·직렬화) 순수 함수
  - `main.js`: `Space`·`↓` 점수 연결, `localStorage` 읽기·쓰기(예외 처리), 이름 입력 폼, 리더보드 그리기
  - `index.html`: 패널 안에 리더보드 목록과 이름 입력 폼 마크업 추가(스크립트 순서·`defer`, 기존 문구·`id`는 그대로)
  - `style.css`: 리더보드·폼 모양(SPEC_02B 디자인 토큰 사용)
  - `test.js`: 새 테스트 추가(기존 46개는 삭제·약화·수정하지 않음)
- `game.js`는 DOM, 타이머, 이벤트, `localStorage`에 접근하지 않는다. 저장소 접근은 `main.js`만 한다.

## 3. 화면 정의

### 점수 [사람 확인 필요: 질문 1]
- 패널의 `점수`가 게임 중 바로 갱신된다.
- 한 번에 지운 줄 수에 따라: 1줄 100, 2줄 300, 3줄 500, 4줄 800.
- `↓`(소프트 드롭): 실제로 한 칸 내려갈 때마다 1점. 바닥에서 눌러 `LANDED`가 되면 0점.
- `Space`(하드 드롭): 내려간 칸 수 × 2점. 이미 더 내려갈 수 없으면 0점.
- 자동 낙하는 0점. 레벨 배수는 없다(SPEC_04).

### 하드 드롭 [사람 확인 필요: 질문 3·4]
- `PLAYING`에서 `Space`를 누르면 블록이 내려갈 수 있는 가장 아래로 한 번에 이동하고 **즉시 고정**된다(`LANDED` 대기 없음).
- 고정 후 처리(줄 제거, `제거한 줄`, 다음 블록, 게임 오버)는 SPEC_02와 같다. SPEC_02B의 고정·줄 제거 연출도 같게 나온다.
- 다음 블록의 첫 자동 낙하는 `Space`를 누른 시점부터 700ms 뒤다.
- `READY`, `LANDED`, `GAME_OVER`에서 `Space`는 아무것도 하지 않는다.
- `Space`의 브라우저 기본 동작(스크롤)은 방향키처럼 항상 막는다. 단 이름 입력칸에 포커스가 있을 때는 어떤 키도 게임이 가로채지 않는다.

### 리더보드 [사람 확인 필요: 질문 12]
- 패널의 `게임 상태` 아래에 `최고 기록` 목록이 항상 보인다. 각 줄: 순위, 이름, 점수, 제거한 줄.
- 기록이 없으면 `아직 기록이 없습니다`가 보인다.
- 이름은 `textContent`로만 넣는다(HTML로 해석하지 않음).

### 게임 오버와 저장 [사람 확인 필요: 질문 6·7·13]
- `GAME_OVER`가 되면 목록 위에 이름 입력 폼(`이름 (2~10자)` 입력칸, `기록 저장` 버튼)이 나타나고 입력칸에 포커스가 간다.
- `기록 저장`(또는 Enter)을 누르면:
  - 이름이 규칙에 맞지 않으면 `이름은 앞뒤 공백을 빼고 2~10자로 입력하세요.`가 보이고 저장하지 않는다.
  - 맞으면 기록을 저장하고 폼을 숨기며, 목록에서 방금 저장한 기록이 금색으로 강조된다.
  - 점수가 TOP 10에 들지 못하면 `TOP 10에 들지 못해 저장되지 않았습니다.`가 보이고 폼을 숨긴다.
- 한 게임에서 저장은 한 번만 된다. 저장하지 않고 `재시작`해도 된다. `재시작`하면 폼과 안내 문구가 사라진다.
- 0점도 저장할 수 있다.

### 저장소 문제 [사람 확인 필요: 질문 10·11]
- 저장된 값이 JSON이 아니거나 배열이 아니면 빈 목록으로 보고, 항목 중 형식이 틀린 것은 버린다. 게임은 정상 동작한다. 다음 저장 때 올바른 값으로 덮어쓴다.
- `localStorage`를 쓸 수 없는 환경(접근 시 예외)이면 게임은 정상 동작하고, 목록 자리에 `이 브라우저에서는 기록을 저장할 수 없습니다.`가 보인다. `기록 저장`을 눌러도 같은 안내만 보인다.

## 4. 상태와 공개 함수

`globalThis.TetrisGame`에 다음을 추가한다. 기존 함수의 동작은 바꾸지 않는다. 특히 `lockPiece`와 `moveDown`은 지금처럼 `score`를 바꾸지 않는다(SPEC_02 테스트 유지). [사람 확인 필요: 질문 2]

### 점수
- `LINE_SCORES`: `[0, 100, 300, 500, 800]`(지운 줄 수가 인덱스)
- `SOFT_DROP_SCORE`: `1`, `HARD_DROP_SCORE`: `2`(칸당)
- `lockAndScore(state, random)`: `lockPiece` 결과에 이번에 지운 줄 수만큼 `LINE_SCORES` 점수를 더한다. `LANDED`가 아니면 입력 상태를 그대로 반환한다.
- `softDrop(state)`: `moveDown`과 같게 움직이고, 실제로 한 칸 내려갔으면 `score` +1. `PLAYING`이 아니면 입력 상태를 그대로 반환한다.
- `hardDrop(state, random)`: `PLAYING`일 때 내려갈 수 있는 만큼 내린 뒤 `score`에 (칸 수 × 2)를 더하고 `lockAndScore`까지 적용한 상태를 반환한다(결과는 `PLAYING` 또는 `GAME_OVER`). `PLAYING`이 아니면 입력 상태를 그대로 반환한다.
- 모든 함수는 입력 상태를 수정하지 않는다.

### 리더보드 [사람 확인 필요: 질문 5·8·9]
- `LEADERBOARD_KEY`: `'tetris-loop.leaderboard.v1'`
- `LEADERBOARD_SIZE`: `10`
- 항목 형식: `{ id: string, name: string, score: number, clearedLines: number, playedAt: string }`. `playedAt`은 ISO 8601 문자열(`new Date().toISOString()`), `id`는 `playedAt`과 무작위 문자열을 이은 값(`main.js`가 만든다).
- `validateName(raw)`: 앞뒤 공백을 지운 뒤 글자 수(코드 포인트 기준)가 2~10이면 `{ ok: true, name }`, 아니면 `{ ok: false, name }`.
- `addLeaderboardEntry(list, entry)`: `entry`를 더해 점수 내림차순, 같은 점수는 `playedAt`이 이른 기록 먼저로 정렬하고 앞의 10개만 남긴 **새 배열**을 반환한다. 입력 배열은 수정하지 않는다.
- `parseLeaderboard(text)`: 저장 문자열을 목록으로 바꾼다. `null`, JSON 오류, 배열이 아님 → `[]`. 형식이 틀린 항목은 버리고, 정렬·10개 자르기를 적용한다.
- `serializeLeaderboard(list)`: `JSON.stringify(list)`.

### main.js 흐름
- 타이머: `PLAYING`이면 `moveDown`, `LANDED`이면 `lockAndScore`.
- `↓`: `softDrop` 후 타이머 초기화(SPEC_02와 같음). `Space`: `hardDrop` 후 타이머 초기화.
- 저장소: 읽기·쓰기는 모두 `try/catch`로 감싼다. 읽기는 `parseLeaderboard(localStorage.getItem(LEADERBOARD_KEY))`.
- 키 처리: 이벤트 대상이 이름 입력칸이면 게임 키 처리와 `preventDefault`를 하지 않는다.

## 7. 자동 검증

`test.js`의 기존 46개를 그대로 두고 다음을 추가한다. 블록 종류는 `random`을 고정하고, 보드는 테스트 안에서 직접 만든다. 리더보드 항목의 `id`·`playedAt`은 테스트에서 직접 넣는다.

- `LINE_SCORES`·`SOFT_DROP_SCORE`·`HARD_DROP_SCORE`·`LEADERBOARD_KEY`·`LEADERBOARD_SIZE` 값
- `lockAndScore` 0·1·2·4줄 점수, 비-LANDED 같은 객체, `lockPiece`·`moveDown` 점수 불변
- `softDrop` +1, 바닥 +0·LANDED, 비-PLAYING 같은 객체
- `hardDrop` 빈 보드 O(+36), 4줄 I(이동×2+800), 이동 0, GAME_OVER, 비-PLAYING 같은 객체, 입력 불변
- `validateName` 경계값(1·2·10·11자, 공백만, trim 후 길이, 한글)
- `addLeaderboardEntry` 정렬·동점·10개 자르기·순위 밖·입력 불변
- `parseLeaderboard` 손상 입력 4종, 틀린 항목 버림, 12개 → 10개, 직렬화 왕복

## 8. 수동 검증 시나리오

각 시나리오는 `index.html`을 브라우저에서 직접 열고 새로고침한 상태에서 시작한다.

### A. 점수
1. `시작` 후 `↓`를 5번 누른다. → `점수`가 5가 된다.
2. 블록을 좌우로 옮겨 맨 아래 1줄을 지운다. → 그 고정에서 `점수`가 100 더 늘고, `제거한 줄`이 1 늘어난다.
3. 손대지 않고 블록이 떨어지게 둔다. → 자동 낙하만으로는 점수가 늘지 않는다.

### B. 하드 드롭
1. `시작` 직후 `Space`를 누른다. → 블록이 바로 바닥에 붙어 고정되고(금빛 반짝임), 새 블록이 나온다. `점수`가 내려간 칸 수 × 2만큼 늘어난다(맨 위에서 바닥까지면 2칸 높이 블록 기준 36).
2. 화면 폭을 줄여 페이지가 길어진 상태에서 `Space`를 누른다. → 페이지가 스크롤되지 않는다.
3. `Space`로 줄을 채워 지운다. → 줄 제거 연출과 줄 점수가 함께 나온다.

### C. 게임 오버와 기록 저장
1. `Space`를 계속 눌러 게임 오버를 만든다. → 패널에 `이름 (2~10자)` 입력칸과 `기록 저장` 버튼이 나타나고 입력칸에 커서가 있다.
2. `별님`을 입력하고 Enter를 누른다. → 폼이 사라지고 `최고 기록` 목록에 `별님`과 점수·줄이 금색 강조로 보인다.
3. 새로고침한다. → 목록에 `별님` 기록이 그대로 있다.
4. 한 번 더 게임 오버를 만들어 다른 이름으로 저장한다. → 점수가 높은 기록이 위에 있다.

### D. 이름 규칙
1. 게임 오버 후 `가`(1자)로 저장한다. → `이름은 앞뒤 공백을 빼고 2~10자로 입력하세요.`가 보이고 목록이 바뀌지 않는다.
2. 공백만 넣고 저장한다. → 같은 안내, 저장 안 됨.
3. 11자 이름을 넣고 저장한다. → 같은 안내, 저장 안 됨.
4. 입력칸에서 방향키·Space를 누른다. → 커서 이동·공백 입력이 정상이고 블록·페이지는 반응하지 않는다.

### E. 손상된 기록
1. 개발자 도구 콘솔에서 `localStorage.setItem('tetris-loop.leaderboard.v1', '{broken')`을 실행하고 새로고침한다. → 오류 없이 화면이 뜨고 `아직 기록이 없습니다`가 보인다.
2. 게임을 해서 기록을 저장한다. → 정상 저장되고 목록에 보인다.

### F. 390px·키 입력·콘솔
1. 390px 폭에서 리더보드·폼을 본다. → 가로 스크롤이 없고 글자가 잘리지 않는다.
2. 콘솔을 본다. → 오류가 없다.

## 9. 안전과 정지 조건

- 프로젝트 폴더 밖 파일을 만들거나 수정하지 않는다. 브라우저 저장은 `localStorage` 한 키만 쓴다.
- 외부 배포, 유료 서비스, 서버 저장을 사용하지 않는다.
- 같은 실패가 두 번 반복되거나 총 세 번 실행해도 완료하지 못하면 중단한다.
- 이 문서에 없는 화면·기술 결정을 해야 하면 추측하지 않고 `[사람 확인 필요]`로 보고한다.
- 범위 밖 기능(레벨, 속도, 미리보기, 일시정지)을 구현해야 하는 상황이면 중단한다.
- 기존 테스트를 바꿔야만 통과하는 상황이면 중단하고 보고한다.

## 앞 SPEC과의 관계 [사람 확인 필요: 질문 4]

- SPEC_01 결정 14 "Space는 막지 않음"은 이 SPEC에서 "Space도 항상 막음(이름 입력칸 제외)"으로 바뀐다.
- SPEC_02 "점수는 `0` 그대로"는 이 SPEC으로 대체된다. 단 `lockPiece`가 점수를 바꾸지 않는다는 SPEC_02 테스트는 그대로 유지·통과한다.
- SPEC_02B의 화면 문구 불변 조건은 기존 문구에 대해 유지하고, 이 SPEC은 리더보드·폼 문구를 새로 더한다.

## 질문 목록 ([사람 확인 필요])

1. 점수 규칙: 제안 1/2/3/4줄 100/300/500/800, `↓` 칸당 1점, `Space` 칸당 2점, 자동 낙하 0점, 레벨 배수 없음(슬라이드 숫자 해석).
2. 기존 테스트 호환: 제안 `lockPiece`·`moveDown`은 그대로 두고 점수를 붙이는 `lockAndScore`·`softDrop`·`hardDrop`을 새로 추가(SPEC_02의 "lockPiece는 score를 바꾸지 않음" 테스트 유지).
3. 하드 드롭: 제안 즉시 고정(LANDED 대기 없음), 다음 첫 낙하는 700ms 뒤, `LANDED`·`READY`·`GAME_OVER`에서는 무시.
4. `Space` 기본 동작: 제안 항상 막음(SPEC_01 결정 14 변경). 이름 입력칸에 포커스가 있으면 어떤 키도 가로채지 않음.
5. 이름 규칙: 제안 앞뒤 공백 제거 후 2~10자(코드 포인트 기준), 문자 종류 제한 없음, 가운데 공백 허용.
6. 저장 시점·횟수: 제안 `GAME_OVER` 때 폼 표시·자동 포커스, 게임당 1회 저장, 저장 없이 재시작 가능, 재시작하면 폼 숨김.
7. TOP 10 밖 점수: 제안 저장 시도 시 `TOP 10에 들지 못해 저장되지 않았습니다.` 안내 후 폼 숨김.
8. 정렬: 제안 점수 내림차순, 동점은 `playedAt`이 이른(먼저 세운) 기록 먼저, 11번째부터 버림.
9. 저장 형식: 제안 키 `tetris-loop.leaderboard.v1`, 최대 10개 JSON 배열, 항목 `{ id, name, score, clearedLines, playedAt }`, `playedAt`은 ISO 8601 문자열, `id`는 `playedAt` + 무작위 문자열.
10. 손상 데이터: 제안 JSON 오류·배열 아님 → 빈 목록, 형식이 틀린 항목은 버림, 다음 저장 때 덮어씀.
11. `localStorage` 사용 불가: 제안 게임 정상, `이 브라우저에서는 기록을 저장할 수 없습니다.` 안내.
12. 화면 배치·문구: 제안 패널의 `게임 상태` 아래 `최고 기록` 목록(순위·이름·점수·줄), 빈 목록 `아직 기록이 없습니다`, 폼 `이름 (2~10자)`·`기록 저장`, 방금 저장한 기록 금색 강조, SPEC_02B 토큰 사용.
13. 0점 기록: 제안 저장 가능.
