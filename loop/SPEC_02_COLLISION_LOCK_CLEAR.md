# SPEC 02 — 충돌, 고정, 줄 제거, 게임 오버

## 1. 목표

- 하는 일: 블록이 고정된 블록과 겹치지 않게 움직이고, 더 내려갈 수 없으면 보드에 고정된 뒤 가득 찬 줄이 지워지고 다음 블록이 나온다. 다음 블록이 놓일 자리가 막혀 있으면 게임 오버가 되고 `재시작`으로 처음부터 다시 한다.
- 하지 않는 일: 점수 계산, 하드 드롭, 리더보드, 레벨·속도 변화, 다음 블록 미리보기, 일시정지는 구현하지 않는다.

## 2. 기술과 파일 구조

- SPEC_00의 기술 제약과 파일 구조를 그대로 따른다(HTML5, CSS, 브라우저 기본 JavaScript, 외부 라이브러리·빌드 없음).
- 새 파일을 추가하지 않는다. 다음 파일만 수정한다.
  - `game.js`: 충돌 판정, 고정, 줄 제거, 다음 블록 생성, 게임 오버 순수 함수
  - `main.js`: 타이머에서 고정 처리 호출, 고정 블록 그리기, 버튼 상태, 제거한 줄 표시
  - `style.css`: 필요할 때만 수정
  - `test.js`: 새 테스트 추가(SPEC_00·SPEC_01 테스트 29개는 삭제·약화·수정하지 않음)
- `index.html`, `test.html`의 스크립트 불러오는 순서와 `defer`는 바꾸지 않는다.
- `game.js`는 DOM, 타이머, 이벤트에 접근하지 않는다.

## 3. 화면 정의

- 시작 전 화면과 `시작` 버튼 동작은 SPEC_01과 같다.
- 고정된 블록은 보드에 남아 그 블록 종류의 색(SPEC_01의 7색)으로 표시된다. [사람 확인 필요: 질문 3]
- 움직이는 블록은 고정된 블록과 겹치지 않는다.
  - `←`, `→`: 옆 칸에 고정된 블록이 있으면 움직이지 않는다.
  - `↑`: 회전 결과가 고정된 블록과 겹치면 회전하지 않는다(벽 킥 없음, SPEC_01과 같음).
  - 자동 낙하와 `↓`: 바로 아래 칸에 고정된 블록이 있거나 바닥이면 `LANDED`가 된다(SPEC_01과 같음).
- 고정 시점 [사람 확인 필요: 질문 1·2]
  - `LANDED`가 된 뒤 다음 낙하 타이머 때(700ms 뒤) 블록이 보드에 고정된다.
  - `LANDED`인 동안 방향키는 블록을 바꾸지 않고, 버튼은 비활성이다.
  - `↓`로 `LANDED`가 된 경우에도 그 `↓`가 타이머를 초기화하므로 고정은 누른 시점부터 700ms 뒤다.
- 고정 직후 순서
  1. 블록의 4칸이 보드에 쓰인다.
  2. 가득 찬 줄(10칸 모두 채워진 행)이 모두 지워지고, 그 위의 행들이 지워진 줄 수만큼 내려오며, 맨 위에 빈 행이 채워진다. [사람 확인 필요: 질문 4]
  3. `제거한 줄` 표시가 지워진 줄 수만큼 늘어난다. 점수는 `0` 그대로다(점수는 SPEC_03).
  4. 다음 블록 하나가 생성 위치에 나타나고 상태가 `PLAYING`이 된다. 첫 자동 낙하는 고정 시점부터 700ms 뒤다. [사람 확인 필요: 질문 5]
  5. 다음 블록의 생성 위치가 고정된 블록과 겹치면 다음 블록을 놓지 않고 `GAME_OVER`가 된다. [사람 확인 필요: 질문 6]
- 게임 오버 [사람 확인 필요: 질문 7·8]
  - 상태 표시가 `GAME_OVER`가 되고 낙하 타이머가 멈춘다.
  - 보드에는 고정된 블록만 보이고, 새 블록은 그려지지 않는다. 별도 안내 문구나 덮개 화면은 없다.
  - 방향키를 눌러도 보드가 바뀌지 않는다(방향키 기본 스크롤은 계속 막는다).
  - 버튼 문구가 `재시작`으로 바뀌고 활성화된다.
- 버튼 상태 [사람 확인 필요: 질문 8]
  - `READY`: `시작`·활성 / `PLAYING`, `LANDED`: `시작`·비활성 / `GAME_OVER`: `재시작`·활성
- `재시작`을 누르면 빈 보드, 점수 `0`, 제거한 줄 `0`, 새 블록, `PLAYING`, 새 타이머 하나로 한 번에 초기화된다(SPEC_01과 같음).

## 4. 상태와 공개 함수

`globalThis.TetrisGame`에 다음을 추가하거나 바꾼다. SPEC_00·SPEC_01의 값과 함수 이름은 유지하고, SPEC_01 테스트 29개가 그대로 통과해야 한다.

### 보드 값 [사람 확인 필요: 질문 3]
- 빈 셀은 `0`(SPEC_00과 같음). 고정된 셀은 그 블록 종류 문자(`'I'`, `'O'`, `'T'`, `'S'`, `'Z'`, `'J'`, `'L'`)다.

### 함수
- `canPlace(board, piece)`: 블록의 4개 셀이 모두 보드 안(0~19행, 0~9열)이고 해당 `board` 셀이 모두 `0`이면 `true`.
- `moveLeft`, `moveRight`, `rotateClockwise`: 판정을 `isInsideBoard(piece)` 대신 `canPlace(state.board, piece)`로 한다. 그 밖의 동작은 SPEC_01과 같다(불가능하면 같은 객체).
- `moveDown(state)`: 한 칸 아래가 `canPlace`이면 내려가고, 아니면 `status`만 `LANDED`인 새 상태를 반환한다. 그 밖의 동작은 SPEC_01과 같다.
- `clearLines(board)`: `{ board, cleared }`를 반환한다.
  - `board`: 가득 찬 행을 모두 지우고 남은 행의 순서를 유지한 채 아래로 모은 뒤, 맨 위를 빈 행으로 채운 새 20×10 보드(행 배열은 서로 독립).
  - `cleared`: 지운 행 수(0~4).
  - 입력 `board`는 수정하지 않는다.
- `lockPiece(state, random)`: `LANDED`일 때만 동작하고, 그 밖에는 입력 상태를 그대로 반환한다.
  1. `activePiece`의 4칸을 종류 문자로 쓴 새 보드를 만든다.
  2. `clearLines`를 적용하고 `lines`에 `cleared`를 더한다. `score`는 바꾸지 않는다.
  3. `random`으로 다음 종류를 골라 생성 위치(rotation 0)에 블록을 만든다. 생략하면 `Math.random`.
  4. 그 블록이 `canPlace`이면 `status: PLAYING`, `activePiece`: 새 블록.
  5. 아니면 `status: GAME_OVER`, `activePiece: null`.
  - 입력 상태와 그 `board`, `activePiece`는 수정하지 않는다.
- `restartGame(state, random)`: `LANDED`(SPEC_01 호환) 또는 `GAME_OVER`이면 새 게임을 반환한다. 그 밖에는 입력 상태를 그대로 반환한다.
- `GAME_OVER` 상태에서 `startGame`, `moveLeft`, `moveRight`, `moveDown`, `rotateClockwise`, `lockPiece`는 입력 상태를 그대로 반환한다.

### main.js 흐름
- 낙하 타이머가 울릴 때: `PLAYING`이면 `moveDown`, `LANDED`이면 `lockPiece`. 결과가 `GAME_OVER`이면 타이머를 멈춘다.
- 화면은 `board`의 고정 셀(종류 색)과 `activePiece`를 합쳐 그린다.
- 무작위 주입은 SPEC_01 결정 15와 같다(`main.js`는 `random`을 넘기지 않음).

## 7. 자동 검증

`test.js`의 기존 29개 테스트를 그대로 두고 다음을 추가한다. 보드는 테스트 안에서 직접 만들고(`{ ...createInitialState(), board }`), 블록 종류는 `random`을 고정해서 고른다.

- `canPlace`: 빈 보드 생성 블록 `true` / 보드 밖 `false` / 고정 셀과 겹침 `false`
- 고정 셀 옆으로 `moveLeft`·`moveRight` 불가, 고정 셀 위에서 `moveDown` → `LANDED`, 고정 셀과 겹치는 회전 불가
- 바닥 O `lockPiece` → 보드 쓰기·새 블록·`PLAYING`
- `lockPiece` 비-LANDED 같은 객체, 입력 불변
- 한 줄·두 줄·네 줄 제거, 떨어진 두 줄 `clearLines`, 가득 찬 줄 없음
- `clearLines` 입력 불변·20×10·행 독립
- `lines` 누적, `score` 불변
- 생성 위치가 막히면 7종 모두 `GAME_OVER`·`activePiece: null`·방금 고정한 블록이 보드에 남음
- 생성 위치 밖만 막힘 → `PLAYING`, 줄 제거로 생성 위치가 비면 `PLAYING`
- `GAME_OVER`에서 6개 함수 같은 객체
- `restartGame`: `GAME_OVER` → 새 게임

## 8. 수동 검증 시나리오

각 시나리오는 `index.html`을 브라우저에서 직접 열고 새로고침한 상태에서 시작한다. 기대 결과가 하나라도 다르면 실패로 기록한다.

### A. 고정과 다음 블록
1. `시작`을 누르고 손대지 않는다. → 블록이 바닥에 닿으면 상태가 잠깐(1초 이내) `LANDED`였다가 블록이 그 자리에 같은 색으로 남는다.
2. 같은 때 → 맨 위 가운데에 새 블록이 나타나고 상태가 `PLAYING`, 버튼은 `시작`·비활성이다.
3. 계속 지켜본다. → 새 블록도 한 칸씩 떨어진다.

### B. 쌓기와 충돌
1. `시작` 후 첫 블록이 바닥에 고정될 때까지 기다린다.
2. 다음 블록을 `←`/`→`로 첫 블록 바로 위로 옮기고 기다린다. → 첫 블록 위에 겹치지 않고 얹혀 고정된다.
3. 다음 블록을 고정된 블록 바로 옆 높이까지 내린 뒤 고정된 블록 쪽으로 `←`/`→`를 누른다. → 고정된 블록 안으로 들어가지 않는다.
4. 고정된 블록 바로 옆에서 `↑`를 눌러 회전하면 겹치게 되는 위치를 만들고 `↑`를 누른다. → 회전하지 않는다.

### C. 줄 제거
1. `시작` 후 블록을 좌우로 옮겨 맨 아래 줄 10칸을 모두 채운다(최대 5분).
2. 줄이 가득 찬 블록이 고정된다. → 그 줄이 사라지고, 그 위에 있던 칸들이 한 줄씩 내려온다.
3. 패널을 본다. → `제거한 줄`이 1 늘었다. 점수는 `0` 그대로다.

### D. 게임 오버
1. `시작` 후 좌우 이동 없이 `↓`를 계속 눌러(누르고 있어도 된다) 블록을 가운데에 쌓는다.
2. 쌓인 블록이 맨 위에 닿는다. → 새 블록이 나타나지 않고 상태가 `GAME_OVER`가 된다.
3. 3초 기다리고 방향키를 누른다. → 보드가 바뀌지 않는다.
4. 버튼을 본다. → 문구 `재시작`, 활성.

### E. 게임 오버 후 재시작
1. D를 따라 `GAME_OVER`를 만든 뒤 `재시작`을 누른다. → 빈 보드, 점수 `0`, 제거한 줄 `0`, 맨 위 가운데 새 블록, `PLAYING`, 버튼 `시작`·비활성.
2. 손대지 않는다. → 10초 시점에 첫 블록이 아직 바닥에 닿지 않았다(낙하가 빨라지지 않음).

### F. 390px·스크롤·콘솔
1. 화면 폭을 390px로 줄인다. → 가로 스크롤이 없다.
2. 페이지가 화면보다 길어진 상태에서 `GAME_OVER`까지 진행하며 방향키를 누른다. → 페이지가 스크롤되지 않는다.
3. 콘솔을 본다. → 오류가 없다.

## 9. 안전과 정지 조건

- 프로젝트 폴더 밖 파일을 만들거나 수정하지 않는다.
- 외부 배포와 유료 서비스를 사용하지 않는다.
- 같은 실패가 두 번 반복되거나 총 세 번 실행해도 완료하지 못하면 중단한다.
- 이 문서에 없는 화면·기술 결정을 해야 하면 추측하지 않고 `[사람 확인 필요]`로 보고한다.
- 범위 밖 기능(점수, 하드 드롭, 리더보드, 레벨·속도, 미리보기, 일시정지, 벽 킥)을 구현해야 하는 상황이면 중단한다.
- SPEC_01 테스트를 바꿔야만 통과하는 상황이면 중단하고 보고한다.

## 앞 SPEC과의 관계 [사람 확인 필요: 질문 9]

이 SPEC을 실행하면 SPEC_01의 다음 화면 조건은 더 이상 성립하지 않는다.

- `LANDED`가 되면 낙하 타이머가 멈춘다 → 이제 다음 타이머 때 고정된다.
- `LANDED`에서 버튼이 `재시작`·활성 → 이제 `GAME_OVER`에서만 `재시작`·활성이다.
- SPEC_01 시나리오 A-5·A-6, E(LANDED 후 재시작)

제안: 위 조건은 SPEC_02로 대체된 것으로 보고 이후 회귀 검증에서 제외한다. SPEC_01의 자동 테스트 29개는 그대로 유지·통과해야 한다.

## 질문 목록 ([사람 확인 필요])

1. 고정 시점: 제안 `LANDED` 후 다음 타이머(700ms 뒤)에 고정. `LANDED` 동안 키 무시·버튼 비활성. 이 방식이면 SPEC_01 테스트(바닥에서 `LANDED`, `LANDED`에서 board 0)를 바꾸지 않아도 된다. 대안 내려갈 수 없는 즉시 고정(`LANDED`가 보이지 않음) — SPEC_01 테스트 수정이 필요하다.
2. `↓`로 `LANDED`가 될 때: 제안 그 `↓`도 타이머를 초기화해 고정은 누른 시점부터 700ms 뒤.
3. 고정 셀 값과 색: 제안 보드에 종류 문자(`'I'` 등)를 저장하고 그 종류 색으로 그림. 대안 `1` 같은 단일 값과 단일 색.
