# SPEC 05 — 고스트 블록과 홀드

> 근거: 사람이 고른 SPEC 05+ 기능 2개(고스트 블록, 홀드)와 `slides-export.pdf` 68~69쪽에서 읽을 수 있는 영문(`calculateGhostY`, fixture, `PLAYING` `C`, `PAUSED` `GAME_OVER`). 슬라이드 한글은 판독하지 못해 해석이 필요한 곳은 `[사람 확인 필요]`로 남긴다. 7-bag은 이번 범위가 아니다.

## 1. 목표

- 하는 일: 현재 블록이 떨어질 자리를 고스트(윤곽선)로 보여주고, `C` 키로 현재 블록을 보관(홀드)하거나 보관한 블록과 바꾼다.
- 하지 않는 일: 7-bag, 벽 킥, 홀드 관련 점수, 효과음은 구현하지 않는다. 기존 SPEC_00~04 동작과 테스트 65개는 그대로 지킨다.

## 2. 기술과 파일 구조

- SPEC_00의 기술 제약을 따른다.
- 새 파일을 추가하지 않는다. 다음 파일만 수정한다.
  - `game.js`: `calculateGhostY`, `holdPiece`, 상태에 홀드 필드 추가, `lockPiece`의 홀드 가능 초기화
  - `main.js`: 고스트 그리기, `C` 키 처리, 홀드 칸 그리기, 홀드 후 타이머
  - `index.html`: 패널에 `홀드 (C)` 칸 추가(스크립트 순서·`defer`, 기존 줄·문구·`id` 유지, 삭제 줄 없음)
  - `style.css`: 고스트·홀드 칸 모양(SPEC_02B 토큰)

## 3. 화면 정의

### 고스트 블록 [사람 확인 필요: 질문 2]
- 현재 블록이 있을 때, 그 블록이 지금 위치에서 바로 떨어지면 놓일 자리에 같은 모양의 고스트가 보인다.
- 고스트는 현재 블록 색의 2px 윤곽선이고 안은 비어 있다. 현재 블록과 겹치는 칸은 현재 블록이 보인다.
- 이동·회전·낙하할 때마다 고스트도 바로 따라 바뀐다.
- `READY`·`GAME_OVER`에서는 고스트가 없다. `LANDED`에서는 블록과 같은 자리라 고스트가 보이지 않는다.
- 하드 드롭(`Space`)한 블록은 고스트가 있던 자리에 고정된다.

### 홀드 [사람 확인 필요: 질문 3·4·5·6]
- `C` 키(키 위치 `KeyC` 기준, 한글 자판 ㅊ 포함)는 `PLAYING`에서만 동작한다. `READY`·`LANDED`·`PAUSED`·`GAME_OVER`와 이름 입력칸에서는 게임이 가로채지 않는다.
- 홀드 칸이 비어 있으면: 현재 블록이 홀드 칸으로 가고, `다음 블록`의 블록이 생성 위치에 나오며 미리보기가 새 블록으로 바뀐다.
- 홀드 칸에 블록이 있으면: 현재 블록과 홀드 블록을 바꾼다. 꺼낸 블록은 생성 위치·회전 0에서 시작하고, 미리보기는 바뀌지 않는다.
- 블록 하나당 한 번만 홀드할 수 있다. 홀드한 블록이 고정되면 다시 가능하다. 이미 홀드했으면 `C`를 눌러도 아무 일도 없고 홀드 칸이 흐려진다.
- 홀드 직후 자동 낙하 타이머는 새 블록이 나온 것처럼 처음부터 다시 센다.
- 홀드로 나올 블록의 생성 자리가 막혀 있으면 `GAME_OVER`가 된다(고정 때와 같음).
- 점수·줄·레벨은 바뀌지 않는다. `재시작`하면 홀드 칸이 빈다.

### 패널 [사람 확인 필요: 질문 8]
- 패널 맨 위에 `홀드 (C)` 칸과 `다음 블록` 칸이 나란히 있다(둘 다 4×4, 생성 방향, 종류 색).
- 홀드를 이미 쓴 블록 동안 `홀드 (C)` 칸은 흐리게 보인다.

## 4. 상태와 공개 함수

### 상태 확장 [사람 확인 필요: 질문 7]
- `createInitialState()`에 `holdType: null`, `holdUsed: false`를 추가한다. 다른 필드는 그대로.
- `lockPiece`는 결과 상태의 `holdUsed`를 `false`로 되돌린다. 그 밖의 `lockPiece` 동작은 그대로다.
- `restartGame`은 새 상태에서 시작하므로 홀드가 빈다.

### 함수
- `calculateGhostY(board, piece)`: `piece`를 아래로 내렸을 때 `canPlace`인 가장 큰 `row` 값을 반환한다(이미 내려갈 수 없으면 `piece.row`). 입력은 수정하지 않는다.
- `holdPiece(state, random)`: `PLAYING`이고 `holdUsed`가 `false`일 때만 동작한다. 그 밖에는 입력 상태를 그대로 반환한다.
  - `holdType`이 `null`이면: `holdType = 현재 종류`, 새 블록은 `pickTetrominoType(random)`의 종류를 생성 위치·회전 0에.
  - 아니면: 새 블록은 `holdType` 종류를 생성 위치·회전 0에, `holdType = 현재 종류`.
  - `holdUsed: true`. 새 블록이 `canPlace`가 아니면 `status: GAME_OVER`, `activePiece: null`.
  - 입력 상태를 수정하지 않는다.

### main.js 흐름
- 고스트: `render()`에서 `activePiece`가 있으면 `{ ...activePiece, row: calculateGhostY(board, activePiece) }`의 칸에 `ghost-종류` 클래스를 먼저 그리고, 그 위에 현재 블록을 그린다(`piece-` 클래스와 구분).
- `C`: 이벤트 `code`가 `KeyC`이고 대상이 이름 입력칸이 아니며 `PLAYING`이면, 홀드 칸이 비었을 때만 `takeNext()`(SPEC_04 다음 블록)를 넘겨 `holdPiece`를 부르고, 상태가 바뀌었으면 타이머를 다시 시작한다.

## 8. 수동 검증 시나리오

각 시나리오는 `index.html`을 브라우저에서 직접 열고 새로고침한 상태에서 시작한다.

### A. 고스트
1. `시작`을 누른다. → 보드 바닥 쪽에 현재 블록과 같은 모양·색의 윤곽선 고스트가 보인다.
2. `←`/`→`/`↑`를 눌러 본다. → 고스트가 블록을 따라 옮겨지고 돈다.
3. 쌓인 블록 위로 옮긴다. → 고스트가 쌓인 블록 바로 위에 보인다.
4. `Space`를 누른다. → 블록이 고스트가 있던 자리에 고정된다.

### B. 홀드
1. `시작` 후 `C`를 누른다. → 현재 블록이 `홀드 (C)` 칸으로 가고, `다음 블록`에 있던 블록이 맨 위에 나온다.
2. 같은 블록에서 `C`를 다시 누른다. → 아무 일도 없고 홀드 칸이 흐리다.
3. 블록을 고정한 뒤 `C`를 누른다. → 홀드 칸의 블록이 맨 위에 나오고, 방금 블록이 홀드 칸으로 간다. `다음 블록`은 그대로다.
4. `P`로 일시정지한 뒤 `C`를 누른다. → 아무 일도 없다.
5. 게임 오버 후 `재시작`한다. → 홀드 칸이 비어 있다.

### C. 기존 기능 회귀
1. 줄을 지운다. → 금빛 연출, 점수·줄 증가가 전과 같다.
2. 게임 오버 후 이름 `cat별님`을 입력해 저장한다. → `c`가 글자로 입력되고 저장된다.

### D. 390px·콘솔
1. 390px 폭에서 홀드·다음 블록 칸과 고스트를 본다. → 가로 스크롤이 없고 잘리지 않는다.
2. 콘솔을 본다. → 오류가 없다.
