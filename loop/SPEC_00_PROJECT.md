# SPEC 00 — 프로젝트 골격과 게임 화면

## 1. 목표

빈 폴더에 브라우저에서 실행되는 테트리스 프로젝트의 골격과 정적인 게임 화면을 만든다. 이번 단계에서는 움직이는 블록이나 게임 규칙을 구현하지 않는다.

## 2. 기술과 파일 구조

- HTML5, CSS, 브라우저 기본 JavaScript만 사용한다.
- 프레임워크, 번들러, 패키지 매니저, 외부 라이브러리를 사용하지 않는다.
- 패키지 설치, 설정 파일, 개발 서버, 빌드 단계가 없어야 한다.
- `index.html`은 `style.css`, `game.js`, `main.js`를 직접 불러온다.
- `game.js`를 `main.js`보다 먼저 불러오며 두 스크립트에는 `defer`를 사용한다.
- `test.html`은 `game.js`, `test.js`를 직접 불러와 브라우저에서 테스트 결과를 표시한다.

- 최소 파일 구조는 다음과 같다.

```text
tetris-loop-workshop/
├── index.html
├── game.js
├── main.js
├── style.css
├── test.html
└── test.js
```

## 3. 화면 정의

- 페이지 제목은 `TETRIS LOOP`다.
- 데스크톱 화면 **(1440px)**에서 왼쪽에는 게임 보드, 오른쪽에는 상태 패널을 배치한다.
- 게임 보드는 10열×20행, 총 200개의 구분 가능한 셀로 표시한다.
- 상태 패널에는 다음 항목을 표시한다.
  - 점수: `0`
  - 제거한 줄: `0`
  - 게임 상태: `READY`
- 보드 아래에 `시작` 버튼을 표시한다.
- `← → ↓ 이동 · ↑ 회전 · Space 하드 드롭 · P 일시정지` 조작 안내를 **보드 아래에** 표시한다.
- 화면 폭이 좁아지면 보드와 상태 패널을 세로로 배치하며 가로 스크롤이 생기지 않아야 한다.

## 4. 상태와 공개 함수

`game.js`는 다음 값을 `globalThis.TetrisGame` 객체로 공개한다.

- `BOARD_WIDTH`: `10`
- `BOARD_HEIGHT`: `20`
- `GAME_STATUS`: `READY`, `PLAYING`, `LANDED`, `PAUSED`, `GAME_OVER` 값을 가진 상수 객체
- `createEmptyBoard()`: 서로 독립적인 20개 행과 각 행의 10개 셀을 생성한다. 빈 셀 값은 `0`이다.
- `createInitialState()`: 빈 보드, 점수 `0`, 제거한 줄 `0`, 상태 `READY`를 가진 새 상태를 반환한다.

## 5. 범위 밖

- 움직이는 테트로미노
- 키보드 입력
- 타이머와 자동 낙하
- 충돌, 줄 제거, 점수 계산
- 리더보드와 브라우저 저장
- 외부 배포

- [ ] `index.html`을 브라우저에서 직접 열었을 때 콘솔 오류가 없다.
- [ ] `test.html`을 브라우저에서 직접 열었을 때 모든 테스트가 통과한다.
- [ ] `index.html`이 `style.css`, `game.js`, `main.js`를 올바른 순서로 직접 불러온다.
- [ ] 패키지 설치, 개발 서버, 빌드 명령이 필요하지 않다.
- [ ] 게임 보드가 정확히 10열×20행으로 표시된다.
- [ ] 점수 `0`, 제거한 줄 `0`, 상태 `READY`가 표시된다.
- [ ] 시작 버튼과 전체 조작 안내가 표시된다.
- [ ] 브라우저 폭 390px에서 가로 스크롤 없이 내용을 확인할 수 있다.
- [ ] 어떤 블록도 생성되거나 움직이지 않는다.

## 7. 자동 검증

`test.html`과 `test.js`에 작은 브라우저 테스트 러너를 만들고, 통과·실패 개수와 실패 이유를 화면에 표시한다. 다음을 확인한다.

- `globalThis.TetrisGame`과 필수 함수가 존재하는지
- 보드 너비와 높이 상수
- 빈 보드가 20×10 구조이며 모든 셀이 `0`인지
- 두 번 만든 빈 보드가 행 배열을 공유하지 않는지
- 초기 상태의 점수, 줄 수, 게임 상태

## 8. 수동 검증

1. `index.html`을 브라우저에서 직접 열고 화면 정의의 모든 텍스트를 확인한다.
2. 보드의 첫 행과 마지막 행이 각각 10개 셀인지 개발자 도구에서 확인한다.
3. 브라우저 폭을 390px로 줄여 가로 스크롤 여부를 확인한다.
4. 5초간 기다리거나 방향키를 눌러도 보드 상태가 바뀌지 않는지 확인한다.

## 9. 안전과 정지 조건

- 프로젝트 폴더 밖 파일을 만들거나 수정하지 않는다.
- 외부 배포와 유료 서비스를 사용하지 않는다.
- 같은 실패가 두 번 반복되거나 총 세 번 실행해도 완료하지 못하면 중단한다.
