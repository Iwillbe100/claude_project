# SPEC 01 — 블록 생성, 낙하, 이동, 회전

> 이 초안은 승인된 `SPEC_01_START_SPAWN.md`(시작 버튼과 첫 블록 생성)를 대체하는 개정안이다. 기존 SPEC_01의 내용과 결정 6개를 그대로 포함하고, 낙하·이동·회전·재시작을 더한다. (결정 16·17)

## 1. 목표

- 하는 일: `시작`을 누르면 블록 하나가 상단 중앙에 생기고 700ms마다 한 칸씩 떨어진다. 방향키로 좌·우·아래 이동과 시계방향 회전을 하고, 바닥에 닿으면 `LANDED`로 멈추며 `재시작`으로 처음부터 다시 한다.
- 하지 않는 일: 고정 블록과의 충돌, 블록 고정(board에 쓰기), 다음 블록 생성, 줄 제거, 게임 오버, 점수, 하드 드롭은 구현하지 않는다.

## 2. 기술과 파일 구조

- SPEC_00의 기술 제약과 파일 구조를 그대로 따른다(HTML5, CSS, 브라우저 기본 JavaScript, 외부 라이브러리·빌드 없음).
- 새 파일을 추가하지 않는다. 다음 파일만 수정한다.
  - `game.js`: 테트로미노 정의, 생성·이동·회전·낙하 한 칸·재시작 순수 함수, 낙하 간격 상수
  - `main.js`: 버튼 이벤트, 낙하 타이머, 키 입력, 버튼 문구·활성 상태, 화면 갱신
  - `style.css`: 블록 셀 색 표시
  - `test.js`: 새 테스트 추가(기존 테스트는 삭제·약화하지 않음)
- `index.html`, `test.html`의 스크립트 불러오는 순서와 `defer`는 바꾸지 않는다. `index.html`의 버튼 `id="start"`와 조작 안내 문구는 그대로 둔다.
- `game.js`는 DOM, 타이머(`setTimeout`, `setInterval`), 이벤트에 접근하지 않는다. 타이머와 키 입력은 `main.js`만 다룬다.

## 3. 화면 정의

- `시작`을 누르기 전 화면은 SPEC_00과 같다(빈 보드, 점수 `0`, 제거한 줄 `0`, 상태 `READY`, 버튼 `시작` 활성).
- `시작`을 누르면:
  - 상태 표시가 `PLAYING`이 된다. 점수 `0`, 제거한 줄 `0`은 그대로다.
  - 블록 하나(4칸)가 보드 맨 위 행에서 블록 너비 기준 가운데에 빈 셀과 구별되는 색으로 나타난다(4장 생성 위치).
  - `시작` 버튼은 비활성화되어 다시 눌러도 블록이 추가로 생기지 않는다.
  - `PLAYING` 동안 700ms마다 블록이 한 칸 아래로 내려간다.
- 블록 모양은 표준 테트로미노 7종(I, O, T, S, Z, J, L)이고, 색은 종류별 7색이다: I 하늘색, O 노랑, T 보라, S 초록, Z 빨강, J 파랑, L 주황. 정확한 색상 값은 구현에서 정하되 7종이 서로 구별되어야 한다.
- 키 입력(`PLAYING`일 때만 블록에 적용):
  - `←` / `→`: 한 칸 왼쪽 / 오른쪽. 보드 왼쪽·오른쪽 경계를 넘게 되면 움직이지 않는다.
  - `↓`: 한 칸 아래. 누를 때마다 낙하 타이머를 초기화해 다음 자동 낙하는 누른 시점부터 700ms 뒤다.
  - `↑`: 시계방향 90도 회전. 회전 결과가 보드 밖이면 회전하지 않는다. (결정 8·9)
  - `←`, `→`, `↑`는 낙하 타이머를 초기화하지 않는다. (결정 11)
  - 방향키 4개는 게임 상태와 관계없이 항상 브라우저 기본 스크롤을 일으키지 않는다. Space는 막지 않는다. (결정 14)
- 더 내려갈 수 없으면:
  - 상태 표시가 `LANDED`가 되고 낙하 타이머가 멈춘다.
  - 블록은 마지막 위치에 같은 색으로 남는다. (결정 12)
  - 방향키를 눌러도 블록이 바뀌지 않는다.
  - 버튼 문구가 `재시작`으로 바뀌고 활성화된다. (결정 13)
- `재시작`을 누르면 다음이 한 번에 일어난다.
  - 빈 보드, 점수 `0`, 제거한 줄 `0`, 상태 `PLAYING`
  - 새 블록 하나가 생성 위치에 나타난다(종류는 다시 무작위).
  - 이전 타이머는 멈추고 새 타이머 하나만 돈다. 첫 자동 낙하는 누른 시점부터 700ms 뒤다.
  - 버튼은 `시작` 문구로 돌아가고 비활성화된다. (결정 13)
- `READY`, `LANDED` 상태에서는 자동 낙하가 없다.

## 4. 상태와 공개 함수

`globalThis.TetrisGame`에 다음을 추가한다. SPEC_00의 값과 함수는 그대로 유지한다.

### 상태
- `createInitialState()`의 결과에 `activePiece: null`을 추가한다.
- `activePiece`: `{ type, row, col, rotation }`. `rotation`은 `0~3`(0 = 생성 방향, 1 = 시계방향 90도, 2 = 180도, 3 = 270도). 생성 시 `0`.
- 움직이는 블록은 `activePiece`에만 두고 `board`에는 쓰지 않는다. `board`는 앞으로 고정된 블록만 담는다. 화면은 `board`와 `activePiece`를 합쳐 그린다.

### 테트로미노
- `TETROMINO_TYPES`: `['I', 'O', 'T', 'S', 'Z', 'J', 'L']`
- `TETROMINOES`: 종류별 생성 방향(rotation 0)의 4개 셀 상대 좌표 `[행, 열]`.
- `pickTetrominoType(random)`: `TETROMINO_TYPES[Math.floor(random() * 7)]`을 반환한다. 인자를 생략하면 `Math.random`. 7종 균등 무작위(7-bag 같은 분배 규칙은 범위 밖).

### 생성 위치 (블록 너비 기준 상단 중앙)
- 생성 직후 블록의 가장 위 셀은 0행이다.
- 블록 너비가 `w`일 때 가장 왼쪽 셀의 열은 `Math.floor((10 - w) / 2)`다. (결정 7)
- 결과 셀(행, 열):
  - I: (0,3) (0,4) (0,5) (0,6)
  - O: (0,4) (0,5) (1,4) (1,5)
  - T: (0,4) (1,3) (1,4) (1,5)
  - S: (0,4) (0,5) (1,3) (1,4)
  - Z: (0,3) (0,4) (1,4) (1,5)
  - J: (0,3) (1,3) (1,4) (1,5)
  - L: (0,5) (1,3) (1,4) (1,5)
- 모든 종류가 0~1행, 3~6열 안에 놓인다.

### 회전 규칙 (결정 8)
- 표준 SRS의 기본 회전 상태를 쓰고, 벽 킥은 없다.
  - I는 4×4 상자, T·S·Z·J·L은 3×3 상자 안에서 상대 좌표 `(r, c)`를 `(c, N-1-r)`로 바꾼다(N = 상자 크기).
  - O는 회전해도 셀이 바뀌지 않는다.
  - 4번 회전하면 처음 셀로 돌아온다.
- 예(T, 생성 위치에서):
  - rotation 1: (0,4) (1,4) (1,5) (2,4)
  - rotation 2: (1,3) (1,4) (1,5) (2,4)
  - rotation 3: (0,4) (1,3) (1,4) (2,4)
- 예(I, 생성 위치에서 한 칸 내린 뒤 → 셀 (1,3)~(1,6)):
  - rotation 1: (0,5) (1,5) (2,5) (3,5)
- 회전 결과 셀 중 하나라도 0~19행, 0~9열 밖이면 회전하지 않는다. (결정 9)
  - 이 규칙에 따라 I는 생성 직후(0행) 회전하면 셀이 -1행에 걸리므로 회전하지 않고, 한 칸 내려온 뒤부터 회전한다.

### 상수와 함수
- `DROP_INTERVAL_MS`: `700`
- `getPieceCells(piece)`: `piece.rotation`을 반영해 4개 셀의 보드 절대 좌표 `[행, 열]`을 반환한다. `rotation`이 없으면 `0`으로 본다.
- `isInsideBoard(piece)`: 블록의 4개 셀이 모두 0~19행, 0~9열 안이면 `true`.
- `startGame(state, random)`: `READY`이면 `status: PLAYING`, 생성 위치의 `activePiece`(rotation 0)를 가진 새 상태를 반환한다. `board`, `score`, `lines`는 입력과 같다. `READY`가 아니면 입력 상태를 그대로(같은 객체) 반환한다.
- `moveLeft(state)`, `moveRight(state)`: `PLAYING`이고 이동 결과가 보드 안이면 `col`을 1 줄이거나 늘린 새 상태를 반환한다. 그 밖에는 입력 상태를 그대로 반환한다.
- `moveDown(state)`: 자동 낙하와 `↓`가 함께 쓰는 한 칸 낙하.
  - `PLAYING`이고 한 칸 아래가 보드 안이면 `row`를 1 늘린 새 상태를 반환한다.
  - `PLAYING`이고 한 칸 아래가 보드 밖이면 `activePiece`는 그대로, `status`만 `LANDED`인 새 상태를 반환한다. (결정 10)
  - `PLAYING`이 아니면 입력 상태를 그대로 반환한다.
- `rotateClockwise(state)`: `PLAYING`이고 회전 결과가 보드 안이면 `rotation`을 `(rotation + 1) % 4`로 바꾼 새 상태를 반환한다. 그 밖에는 입력 상태를 그대로 반환한다.
- `restartGame(state, random)`: `LANDED`이면 `startGame(createInitialState(), random)`과 같은 결과(빈 새 보드, 점수·줄 `0`, `PLAYING`, 새 `activePiece`)를 반환한다. `LANDED`가 아니면 입력 상태를 그대로 반환한다.
- 위 함수는 모두 입력 상태와 `activePiece`, `board`를 수정하지 않는다.

### 무작위 주입 (결정 15)
- `startGame(state, random)`, `restartGame(state, random)`은 `random`(0 이상 1 미만을 돌려주는 함수)을 받아 블록 종류를 정한다. 생략하면 `Math.random`.
- 테스트는 `random`을 고정해 원하는 종류를 고른다. 예: `() => (i + 0.5) / 7`이면 `TETROMINO_TYPES[i]`.
- `main.js`는 `random`을 넘기지 않는다(`Math.random` 사용).

## 7. 자동 검증

`test.js`의 기존 테스트를 유지하고 다음 테스트를 추가한다. 블록 종류는 `random`을 고정해서 고른다.

- `DROP_INTERVAL_MS === 700`
- 7종 생성 셀이 4장 표와 일치, `rotation === 0`
- I를 `moveLeft` 3번 → 0~3열, 4번째는 같은 객체. `moveRight` 3번 → 6~9열, 4번째는 같은 객체
- 7종 각각 `moveDown`을 반복: `LANDED` 직전까지 `PLAYING`, 가장 아래 셀이 19행인 상태에서 한 번 더 호출하면 셀은 그대로이고 `LANDED`
- T 회전 1·2·3 셀이 4장 예와 일치, 4번 회전하면 처음 셀
- O 회전 후 셀이 그대로
- I 생성 직후 회전은 같은 객체, `moveDown` 1번 뒤 회전하면 (0,5)~(3,5)
- T를 1번 회전하고 `moveLeft`를 같은 객체가 나올 때까지 반복한 뒤 회전 → 같은 객체
- `READY`, `LANDED`에서 네 함수가 같은 객체를 반환
- 각 함수 호출 전후 입력 상태의 `status`, `activePiece.row/col/rotation` 비교
- `LANDED` 상태의 `board`가 모두 `0`
- `restartGame`: `LANDED` → `PLAYING`, 이전과 다른 보드 객체, 모두 `0`, 점수·줄 `0`, 주입한 종류·생성 위치·`rotation 0`. `READY`·`PLAYING`에서는 같은 객체

## 8. 수동 검증 시나리오

각 시나리오는 `index.html`을 브라우저에서 직접 열고 새로고침한 상태에서 시작한다. 기대 결과가 하나라도 다르면 실패로 기록한다.

### A. 시작·생성·자동 낙하·LANDED
1. 화면을 본다. → `READY`, 빈 보드, 점수 `0`, 제거한 줄 `0`, `시작` 버튼 활성.
2. `시작`을 누르고 시계를 본다. → `PLAYING`, 맨 위 가운데에 색이 있는 4칸 블록, 점수·줄 `0`, 버튼 비활성.
3. 비활성 버튼을 다시 누른다. → 블록이 추가로 생기지 않는다.
4. 손대지 않고 지켜본다. → 블록이 한 번에 한 칸씩 내려간다. 10초 시점에 아직 바닥에 닿지 않았다.
5. 계속 기다린다. → 시작 후 15초 안에 블록 아래쪽이 보드 맨 아래 행에 닿고 상태가 `LANDED`가 된다.
6. 3초 더 기다리고 `←` `→` `↓` `↑`를 누른다. → 블록이 그대로다. 버튼 문구가 `재시작`이고 활성이다.

### B. 좌우 이동·벽
1. `시작`을 누른다.
2. `←`를 10번 누른다. → 누를 때마다 한 칸씩 왼쪽으로 가고, 블록 왼쪽 끝이 1열(맨 왼쪽)에 닿은 뒤로는 움직이지 않는다.
3. `→`를 10번 누른다. → 한 칸씩 오른쪽으로 가고, 블록 오른쪽 끝이 10열(맨 오른쪽)에 닿은 뒤로는 움직이지 않는다.

### C. ↓ 이동과 타이머 초기화
1. `시작`을 누른다.
2. `↓`를 약 0.3초 간격으로 5번 누른다. → 누르는 동안 블록이 정확히 5칸 내려간다(자동 낙하가 끼어들지 않음).
3. 손을 뗀다. → 그 뒤로 다시 한 칸씩 자동으로 내려간다.

### D. 회전
1. T 블록이 나올 때까지 새로고침 후 `시작`을 반복한다.
2. `↑`를 1번 누른다. → 위로 튀어나온 칸이 오른쪽으로 간다(시계방향 90도).
3. `↑`를 3번 더 누른다. → 처음 모양으로 돌아온다.
4. `↑`를 1번 누르고 `←`를 끝까지 누른 뒤 `↑`를 누른다. → 회전하지 않는다(보드 밖으로 나가지 않음).

### E. 재시작·타이머 중복 없음
1. 시나리오 A의 1~5를 따라 `LANDED`를 만든다.
2. `재시작`을 누르고 시계를 본다. → 빈 보드, 맨 위 가운데에 새 블록, `PLAYING`, 점수·줄 `0`, 버튼 문구 `시작`·비활성.
3. 손대지 않는다. → 10초 시점에 아직 바닥에 닿지 않았다(낙하가 빨라지지 않음).
4. `LANDED`가 될 때까지 기다렸다가 1~3을 한 번 더 반복한다. → 같은 결과.

### F. 무작위 종류·색
1. 새로고침 후 `시작`을 10번 반복한다. → 서로 다른 종류가 2가지 이상 나온다.
2. 나온 블록의 색이 3장 색 규칙(I 하늘색, O 노랑, T 보라, S 초록, Z 빨강, J 파랑, L 주황)과 맞다.

### G. 390px·스크롤·콘솔
1. 개발자 도구를 열고 화면 폭을 390px로 줄인다. → 가로 스크롤이 없다.
2. 페이지가 화면보다 길어진 상태에서 `시작` 후 `↓`, `↑`를 누른다. → 페이지가 스크롤되지 않는다.
3. 콘솔을 본다. → 오류가 없다.

## 9. 안전과 정지 조건

- 프로젝트 폴더 밖 파일을 만들거나 수정하지 않는다.
- 외부 배포와 유료 서비스를 사용하지 않는다.
- 같은 실패가 두 번 반복되거나 총 세 번 실행해도 완료하지 못하면 중단한다.
- 이 문서에 없는 화면·기술 결정을 해야 하면 추측하지 않고 `[사람 확인 필요]`로 보고한다.
- 범위 밖 기능(고정 블록 충돌, 줄 제거, 점수, 하드 드롭, 벽 킥, 다음 블록 생성)을 구현해야 하는 상황이면 중단한다.
- 기존 테스트를 바꿔야만 통과하는 상황이면 중단하고 보고한다.
