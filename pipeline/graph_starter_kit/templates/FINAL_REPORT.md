## 루프판과 비교

| | 루프판 | 그래프판 | 왜 달라졌나 |
| --- | --- | --- | --- |
| 반복 횟수 | 8 (A 3 · B 2 · C 3) | | 처방 가지는 바퀴로 세지 않는다 → 같은 뜻으로 비교된다 |
| 전체 시간 | 약 40분 | | 병렬 |
| 실패 후 재실행 범위 | 바퀴 전체 | | 체크포인트 |
| 사람 호출 횟수 | 2 | | **3 이 정상** — 게이트 A 1 · B 2 (`proceed` · `done` · `done` 으로 답했을 때. 루프판 2 에 **정성 뒤 확정**이 하나 더). 처방 가지가 한도를 다 쓰면 그 루프의 게이트에 서고, 거기서 `more` · `research` · `rebuild` 를 고르면 같은 게이트에 한 번 더 선다 — 그런 정지 하나마다 +1. 늘어난 수와 이유를 적는다 |
| 정성 회차 | 3 / 3 | | **고정 예산 — 빨라지지 않는다** |
| `verify_all` | exit 0 | | 같은 검사기 |
| 못 채운 칸 | 0건 | | **같아야 정상.** 다만 주소가 틀려서 못 채운 칸(image_dead)은 처방 가지가 줄일 수 있다 |
| 계약 밖 아쉬움 | 1건 | | 검사기가 세지 않는 사람 메모다 (`graph/04_RUN_EVIDENCE.md` 5번) — 못 채운 칸에 섞지 않는다 |

> 못 채운 칸이 같다는 것이 중요합니다. 그래프로 옮긴다고 인터넷에 없는 사진이
> 생기지 않습니다. 그래프가 개선하는 것은 실행 효율과 복구 능력입니다.
> 복구 능력의 예가 규칙 처방 가지입니다 — **주소가 틀려서** 못 채운 칸은 처방 가지가 정해진 절차로
> 줄일 수 있습니다. 있던 사진의 주소를 바로잡는 것이지, 없던 사진이 생기는 것은 아닙니다.
>
> 반복 횟수는 처방 가지가 돌아도 늘지 않습니다. 처방 가지에서 합격하고 돌아온 방문은
> 바퀴(`loop_a_iter` · `loop_b_iter`)로 세지 않기 때문입니다 (history 의
> "처방 가지에서 복귀 — 바퀴를 쓰지 않음"). 그래서 루프판과 같은 뜻으로 비교됩니다.

## 반드시 지키는 것

- `SUCCESS` 가 아니면 성공했다고 쓰지 않는다.
- **못 채운 칸이 있으면 반드시 적는다.** 조용히 넘어가는 것이 가장 나쁜 실패다.
- `live` 가 폴백했으면 적는다. live 결과인 척하지 않는다.
- 실측이 한 번뿐이면 "한 번은 일화" 라고 적는다. 교육생 본인 킷의 처방 가지(STEP 6 · 조건부)는
  보고서 ③ · ③-2 에 [후보] · [패턴 …]이 있을 때만 만들고([일화] · [한 번 — 재수집이 맡으면 된다] 뿐이면
  만들지 않는다), **킷에 넣자고** 적는 것은 서로 다른 실행 3곳 이상에서
  나온 것 또는 원인과 고칠 법이 이미 알려진 실패 축뿐이다.
- **처방 가지가 못 고친 것이 있으면 그대로 적는다.** 한도를 다 써서 게이트로 넘어간 가지는
  `failure_evidence` 원문과 게이트에서 고른 것을 함께 남긴다.
- 실패를 재현한(inject) 실행이면 그렇다고 적는다 — 처방 가지 줄 끝에 `(재현: <이름>)`. 재현한 실행을
  기본 실행인 척 비교표에 올리지 않는다.
- **정성에서 고치지 못한 위반이 있으면 그대로 적는다.** `passN.json` 의 `skipped_fix` 에
  이유가 남아 있다. "3회를 돌았다"만 적고 넘어가지 않는다.
