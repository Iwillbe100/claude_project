# 실측 — 이번 실행에서 실제로 일어난 일

**이 파일이 어디에 처방 가지를 둘지의 근거입니다.**
결정은 '내가 정한 것'이고, 실측은 '현실이 답한 것'입니다.
결정에서 실측을 계산할 수 없기 때문에 값이 있습니다.

---

## 1. 요약

```text
run_id       : 2026-10-23T14-38-25
종료 상태     : SUCCESS
루프 A 반복   : 1 / 상한 3
루프 B 반복   : 1 / 상한 3
전체 반복     : 6
기록된 사건   : 7줄
```

## 2. 실패 유형 분포

실패로 세는 줄: `failure_type` 이 적혀 있거나, 다음 행동이 실패 라우팅(`RETRY` · `RESEARCH` ·
`REVISE_SPEC` · `HITL` · `STOP`)이면서 검사기가 통과하지 않은 줄. 되물음(`REVERSE_QUESTION`) ·
루프 C 남은 회차(`QUALITY`) · 최종 검증 통과(`DONE`) · 출발점 빨간불(`iteration` 0)은 정상 진행이라
세지 않습니다. **아래 3 · 4 · 5 · 7번도 같은 줄만 봅니다.**

기록된 실패가 없습니다 (사건 7줄은 모두 정상 진행입니다).

## 3. 어느 작업이 몇 번 실패했나

실패 기록이 없습니다.

## 4. 같은 오류가 반복됐나

같은 지문이 2회 이상 반복된 기록은 없습니다.

## 5. 바퀴를 돌게 만든 칸 (이력)

기록된 부족 칸이 없습니다.

## 6. 끝내 못 채운 칸

못 채운 칸이 없습니다.

## 7. 그래서 어느 처방 가지가 필요할까 — 자동 제안

아직 처방 가지를 둘 근거가 부족합니다 — 그동안은 재수집(LLM)이 맡습니다. 실행을 더 쌓으세요.

## 8. 루프판 기준선 (그래프판과 비교할 숫자)

그래프 킷 가이드의 **비교표(루프판 vs 그래프판)** 왼쪽 칸을 여기서 옮겨 적습니다.

```text
반복 횟수            5   (A 1 · B 1 · C 3)
전체 시간           약 22분
실패 후 재실행 범위   바퀴 전체
사람 호출 횟수        3
정성 회차            3 / 3
verify_all          exit 0   (A PASS · B PASS · C PASS)
못 채운 칸           0건
계약 밖 아쉬움        (기록 없음 — 내 루프 기록에서 옮겨 적는다)
```

> 시간은 `run_manifest.json` 의 `started_at` → `state/loop_state.json` 의 `updated_at` 입니다.
> 사람 호출은 `events.jsonl` 에서 다음 행동이 되물음(`REVERSE_QUESTION`) · `HITL` 인 줄 수입니다.
> 그래프판의 반복 횟수에는 **처방 가지를 세지 않습니다** (처방 가지에서 합격하고 돌아온 방문은
> 바퀴를 쓰지 않는다). 그래서 이 숫자와 같은 뜻으로 비교됩니다.
