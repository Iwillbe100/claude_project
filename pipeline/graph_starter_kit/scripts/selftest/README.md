# scripts/selftest — 검사기를 검사한다

킷 소유입니다. **고치지 않습니다.**

---

## 왜 있는가

루프 킷 `specs/05_TEST_AND_VERIFIER.md` (88줄) 는 이렇게 적어 두었습니다.

```text
처음부터 통과하는 검사기는 아무것도 검사하지 않는 것입니다.
```

그런데 그 원칙을 **산출물에만** 적용했습니다. `output/` 이 비어 있으면 `SHORT` 가
난다는 것은 확인했지만, **검사행 하나하나가 실제로 물리는지**는 아무도 확인하지
않았습니다. 그래서 이런 일이 있었습니다.

```text
계약에 배치를 선택지 문구 그대로 "우측 툴바" 라고 적었다
   ↓
검사기 안의 == "drawer" 가 어긋났다
   ↓
검사행 6개가 통째로 사라졌다 (실패가 아니라 '없어졌다')
   ↓
판정은 그대로 PASS. 오른쪽 툴바가 없는 화면이 만점을 받았다
```

결과물이 나빠진 것이 아니라 **검사기가 조용히 약해진 것**입니다.
그리고 검사기가 약해진 것은 검사기가 알려 주지 않습니다.

---

## 무엇을 하는가

검사행마다 **그 행을 반드시 빨간불로 만드는 최소 입력**을 하나씩 갖습니다.

```text
world.py          도시 1개 · 관광지 1곳 · 1일짜리 '합격하는 최소 세계'
run_selftest.py   그 세계를 한 군데씩 망가뜨리고, 의도한 그 행이 실패하는지 본다
```

핵심은 "실패했다"가 아니라 **"의도한 그 행에서 실패했다"** 입니다.
다른 이유로 실패했다면 그 검사행은 여전히 죽어 있는 것입니다.

```python
hits = [행 for 행 in 결과.rows if "기능2 우측 툴바" in 행.name and not 행.passed]
assert hits, "툴바를 지웠는데 그 행이 실패하지 않았다 — 이 검사행은 죽어 있다"
```

## 어떻게 돌리는가

```bash
python scripts/selftest/run_selftest.py
python scripts/selftest/run_selftest.py --only 툴바     # 이름으로 골라 돌린다
python scripts/selftest/run_selftest.py --keep          # 임시 폴더를 남긴다
```

| 종료 코드 | 뜻 | 다음 행동 |
| --- | --- | --- |
| `0` | 모든 검사행이 살아 있다 | 루프를 시작해도 된다 |
| `1` | 죽은 검사행이 있다 | **결과물이 아니라 검사기를 고친다** |

`1` 이 나오면 그것은 교육생의 잘못이 아닙니다. 그 입력이 통과한다면 같은 실수가
실제 실행에서도 통과한다는 뜻이므로, 루프를 시작하기 전에 검사기부터 고칩니다.

## 검사행을 새로 만들면

검사기에 행을 하나 더할 때는 **그 행을 빨간불로 만드는 입력도 같이** 넣습니다.
넣지 않으면 그 행은 처음부터 죽어 있을 수 있고, 아무도 그것을 모릅니다.

`run_selftest.py` 의 `CASES` 에 이 모양으로 한 줄 더합니다.

```python
{
    "name": "무엇을 망가뜨리는가",
    "why":  "왜 이것이 통과하면 안 되는가",
    "checker": "count" | "page" | "quality",
    "expect_row": "실패해야 하는 행 이름의 일부",   # 또는 expect_error
    "mutate": lambda root: ...,
}
```
