## 읽기 3 — 이미 정해 둔 것 (읽고 넘어가기)

### (1) 한 바퀴 = AORR 네 걸음 (고정)

```text
Act      첫 바퀴: 작업 목록을 순서대로 한 번씩     ← TASK-입력읽기 → … → TASK-일정수집
         다음 바퀴: 지적된 칸의 작업만 다시        ← TASK-명소수집 (지적된 칸만)
Observe  검사기를 한 번 돌리고 종료 코드를 읽는다   ← exit 2
Reason   실패 유형을 하나 고른다                  ← INFORMATION_INSUFFICIENT
Repeat   정해진 다음 행동을 한다                  ← RESEARCH (부족한 칸만)
```

> 판정기는 그 루프의 결과물 **전체**를 한 번에 봅니다 (루프 A 는 `research_data.json` 전체).
> 그래서 작업 하나마다 판정하지 않습니다 — 첫 수집이 끝나기 전의 판정은 SHORT 가 정해져 있어
> 상한 안에서 바퀴만 씁니다.

### (2) 실패 유형별 다음 행동 (고정)

| 실패 유형 | 뜻 | 다음 행동 |
| --- | --- | --- |
| `CODE_ERROR` | 코드가 틀림 | `RETRY` — 최소 수정 |
| `TEST_ERROR` | 검사기가 이상함 | `HITL` — 검사기를 마음대로 고치지 않는다 |
| `SPEC_CONFLICT` | 명세끼리 어긋남 | `REVISE_SPEC` — 명세부터 고침 |
| `ENVIRONMENT_ERROR` | 실행 환경 문제 | `HITL` |
| `PERMISSION_ERROR` | 권한 없음 | `HITL` |
| `INFORMATION_INSUFFICIENT` | 정보가 모자람 | `RESEARCH` — **부족한 칸만** 다시 |
| `UNKNOWN_ERROR` | 분류 불가 | `STOP` |

### (3) 상한에 걸렸을 때 — 되물음으로 넘긴다 (고정)

`RESEARCH`를 상한만큼 돌았는데도 못 채우면 **그냥 멈추지 않고 물어봅니다.**

```text
[되물음] 루프 A를 3바퀴 돌았지만 2칸을 못 채웠습니다.
  못 채운 것 : 후에 황제릉 사진 · 다낭 일정 근거 1건
  같은 오류가 2번 반복되었습니다 (더 돌려도 결과가 같을 가능성이 큽니다)
  고르세요
   [1] 한 바퀴만 더 돈다
   [2] 부족한 채로 루프 B로 넘어간다   ← 권장
   [3] 여기서 멈춘다
```

> **왜 [2]가 권장인가?** 인터넷에 없는 정보는 몇 바퀴를 더 돌아도 없습니다.
> 사진이 없는 관광지는 대체 박스로 보여 주고 **나머지를 완성하는 편**이 낫습니다.
> 이때 못 채운 칸은 **보고서에 그대로 적힙니다.** 조용히 넘어가는 것이 아닙니다.

### (4) 제자리걸음을 기계가 알아채는 법 (고정)

```text
오류 지문 = sha256(검사기 이름 + 실패 유형 + 오류 첫 줄)

같은 지문이 반복 = 아무 진전이 없다는 뜻
```

### (5) 그 밖의 고정 규칙

```text
첫 바퀴는 작업 목록을 순서대로 한 번씩 돌린 뒤 판정기를 한 번 돌린다
다음 바퀴부터는 부족으로 지적된 칸의 작업만 다시 한다 (RESEARCH = 부족한 칸만)
지적되지 않은 칸은 손대지 않는다 · 원인을 추측해 여러 곳을 한꺼번에 고치지 않는다
반복 기록은 evidence/runs/<run_id>/events.jsonl 에 한 줄씩
```

### (6) 루프 C는 3회 고정이다 (고정) — 왜 상한이 아니라 횟수인가

앞 두 루프는 **검사기가 통과하면** 끝납니다. 루프 C에는 그런 통과 선이 없습니다.

```text
"품질 8점 이상이면 통과" 로 닫으면?
   글을 쓴 쪽이 자기 글에 점수를 준다  →  조건⑤(판정 독립) 붕괴

그래서 회차로 닫는다.
   반복 횟수는 관측 가능하고, 늘기만 하고, 반드시 3에 닿는다
   종료 조건이 갖춰야 할 세 가지를 그대로 만족한다
```

| | 루프 A · B의 상한 | 루프 C의 3회 |
| --- | --- | --- |
| 뜻 | **최대** — 여기까지만 돈다 | **최소이자 최대** — 꼭 3번 돈다 |
| 통과 조건 | 검사기 exit 0 | 3회를 규율대로 기록 |
| 정하는 사람 | 교육생 | **킷 고정** |

**회차마다 렌즈가 다릅니다.** 같은 눈으로 세 번 보면 2회차부터 "이상 없음"만 나옵니다.

```text
1회차  내용이 실한가        반복 · 취향 연결 · 뺀 이유 · 상세 3요소
2회차  실행 가능하고 사실인가  일정 현실성 · 근거 일치 · 도시 차별화 · 실용 누락
3회차  독자 관점에서 완결인가  동행 반영 · 계약 무결 + 앞 회차가 되돌아가지 않았는지
```

**되돌아감 방지가 이 루프의 안전핀입니다.**

```bash
python scripts/verify_all.py --skip-quality      # 회차 끝마다 반드시
```

`exit 0`이 아니면 **그 회차의 수정을 되돌립니다.** 이 검사가 없으면
정성 개선이 정량 계약을 깨뜨리는 루프가 됩니다.

> 규율 10가지는 `QUALITY_RUBRIC.md`, 회차 기록 양식은 `templates/QUALITY_PASS.md`.
> **둘 다 킷 고정이라 결정이 늘어나지 않습니다.**
