## 읽기 3 — 이미 정해 둔 것 (읽고 넘어가기)

### (1) 데이터마다 "충족"의 뜻이 다르다 — 이게 이 STEP의 핵심

```text
환율은 오늘 하나뿐이다.        →  1건 들어오면 그게 곧 충족이다.
그 나라 역사 이야기는 많다.    →  여러 건을 모아야 내용이 풍성해진다.
지금 유행하는 질병은 없을 수도. →  없으면 없다고 확인한 것으로 충족이다.
사진은 있거나 없거나 둘 중 하나.→  1장 걸리면 충족이다.
```

그래서 항목마다 **특성(kind)** 을 붙여 두었습니다.

| 특성 | 뜻 | 충족 판정 |
| --- | --- | --- |
| `다건` | 여러 건을 모아야 풍성해지는 것 | 목표 개수 이상 **+ 서로 다른 출처 2곳 이상** |
| `단건` | 사실이 하나뿐인 것 | **1건이면 끝** |
| `조건부` | 지금은 없을 수도 있는 것 | **확인했다는 표시**만 있으면 통과 (0건도 통과) |
| `자산` | 이미지처럼 있고 없고인 것 | 주소가 **실제로 열리는 것까지 확인**되면 통과 |

> 근거 1건은 계약이 정한 글자 수를 넘어야 세어 줍니다. "좋음" 한 마디는 세지 않습니다.

**`자산`의 판정이 바뀐 이유 — 실제로 있었던 일**

```text
계약    "주소 + 대체 문구가 있으면 통과"
결과    이미지 11장 전부 죽음 (404 10장 · 400 1장). 그런데 검사는 SUCCESS.

원인    모델이 주소를 조회로 얻지 않고 형식에 맞춰 지어냈다.
        .../thumb/8/8c/Moraine_Lake_17092005.jpg/1280px-...   ← 8/8c 는 알 수 없는 값이다
        .../thumb/c/c5/Moraine_Lake_17092005.jpg/1280px-...   ← 실제로는 c/c5 였다
```

파일도 사진도 **실재했습니다.** 알 수 없는 한 조각을 지어낸 것이 전부였습니다.
그래서 이제 `자산`은 **"열어 본 기록"**이 있어야 통과합니다.

### (3) 어디에 저장하나 (고정) — 설명만 합니다. 고르지 않아도 됩니다

모은 정보는 **`output/research_data.json` 파일 하나**에 모입니다.
세기 쉬우라고 **기능별로 칸을 나눠 두었습니다.**

```json
{
  "request": { "country": "…", "days": 5, "style": { … } },

  "country_intro": {
    "매력":   { "items": [ {"text": "…", "source_url": "…", "source_name": "…"} ] },
    "역사":   { "items": [ … ] },
    "환율":   { "items": [ … ] },
    "국가상태": { "checked": true, "items": [] },
    "국기이미지": { "asset": {"url": "…", "alt": "…", "verified": {…}} }
  },

  "cities": [
    {
      "name": "다낭",
      "why_selected": "왜 이 도시를 골랐는가",
      "spots": [
        { "name": "미케 비치",
          "items": [ {"text": "…", "source_url": "…"} ],
          "image": {"url": "…", "alt": "…",
                    "verified": {"status": 200, "content_type": "image/jpeg",
                                 "checked_at": "2026-09-05T15:02:11"}},
          "detail": "관광지 상세 소개 본문" }
      ],
      "preference_note": "취향 연결 설명 (줄 단위)",
      "itinerary": {
        "items": [ {"text": "…", "source_url": "…"} ],
        "days": [ {"day": 1, "blocks": [
          {"start": "09:00", "end": "11:30", "kind": "명소",
           "spot": "미케 비치", "why": "왜 이 시간에 여기인지"},
          {"start": "12:00", "end": "13:00", "kind": "식사",
           "place": "…", "why": "…"}
        ]} ]
      }
    }
  ]
}
```

> **이미지 칸은 자리마다 규격이 다릅니다.** 화면을 그리는 쪽이 그렇게 읽기 때문입니다.
>
> | 자리 | 규격 |
> | --- | --- |
> | `country_intro.국기이미지` · `대표이미지` | `{"asset": {"url": …, "alt": …, "verified": {…}}}` |
> | `cities[].spots[].image` | `{"url": …, "alt": …, "verified": {…}}` (감싸지 않습니다) |
>
> 2026-09-09부터 `check_information_count.py`가 이 규격을 **강제합니다.** 예전에는 둘 다
> 통과시켰는데, 관광지 이미지를 `asset`으로 감싸면 정보량은 PASS인데 화면에 사진이 안
> 그려져 **루프 A는 통과하고 루프 B만 실패하는** 교착이 났습니다. 이제 루프 A가 그 자리에서
> 잡아 그 도시만 재수집으로 돌려보냅니다.


> **왜 이렇게 나눴나?** 세기 쉬워서입니다.
> `cities[0].spots` 의 길이를 세면 그게 곧 "다낭의 관광지 개수"입니다.
> 한 덩어리로 뭉쳐 두면 무엇이 부족한지 알 수 없고, 루프는 **전부 다시** 모아야 합니다.

> **일정의 `days` 는 도시마다 여행 일수만큼 있습니다.** 도시들을 합쳐서 세지 않습니다.
> 세 도시를 합쳐 7일이면 "어느 도시로 갈까"를 고를 수 없기 때문입니다.

### (5) 숫자만 채우면 생기는 함정 세 가지 (고정)

개수를 채웠는데도 읽을 것이 없는 결과물이 나옵니다. 세 가지가 원인이었습니다.

| 함정 | 실제로 일어난 일 | 킷이 거는 잠금 |
| --- | --- | --- |
| **기준선에서 멈춤** | 관광지 상세 하한이 120자라 130자에서 문장을 끊었다 (지금 300자) | 하한을 계약에 두고 올림 |
| **분량 채우기 복제** | 30줄 중 21줄이 번호만 다른 같은 문장 | 고유 줄 비율 · 글 사이 유사도 |
| **주소만 있는 이미지** | 11장 전부 죽었는데 통과 | `verified` 기록 필수 |

```text
하한을 올리기만 하면    글자 수를 채우려고 같은 말을 늘려 쓴다
중복만 막으면          짧은 문장을 서로 다르게 여러 줄 쓴다
그래서 둘을 같이 건다.  그리고 이미지는 열어 본 기록을 요구한다
```

<div></div>

**이미지 주소는 손으로 만들지 않습니다.**

```text
금지   upload.wikimedia.org/...  (thumb 이든 원본이든 전부 — 조회로 얻은 주소도 검사기가 SHORT)
권장   https://commons.wikimedia.org/wiki/Special:FilePath/<파일명>?width=1024
```

권장 형태는 **파일명만 있으면 됩니다.** 지어낼 조각이 없어서 애초에 틀릴 수가 없고,
없는 파일이면 그대로 404가 나므로 확인도 깨끗합니다.

> **검사기는 인터넷에 접속하지 않습니다.** 대신 *"접속해서 확인한 기록"*을 봅니다.
> 그래야 판정이 빠르고, 인터넷이 없는 곳에서도 같은 결과가 나옵니다.
> 확인은 **모으는 사람의 일**이고, 확인했다는 증거를 남기는 것이 계약입니다.
