## 읽기 1 — 이 STEP에서 정하는 것

루프가 일을 시작하려면 **딱 세 가지**를 알아야 합니다.

```text
국가          어느 나라인가
여행 일수     며칠짜리인가
여행 스타일   무엇을 좋아하고 무엇을 싫어하는가
```

이 셋이 없으면 루프는 아무것도 못 합니다. 그래서 **필수 입력**입니다.
여기서 정한 스타일이 **도시를 고르는 기준**이 되고, 마지막에 **"왜 이 도시를 골랐는지"** 설명하는 근거가 됩니다.

## 읽기 3 — 이미 정해 둔 것 (읽고 넘어가기)

고민하지 않아도 됩니다. 미리 고정했습니다.

| 항목 | 고정값 |
| --- | --- |
| 반드시 받아야 하는 것 | **국가 · 여행 일수 · 여행 스타일** 세 가지 |
| 스타일을 적는 곳 | [`USER_REQUEST.md`](../USER_REQUEST.md) — 킷 폴더 맨 위에 있습니다 |
| 출력 언어 | 한국어 |
| **출처 등급을 따지지 않는다** | 여행 정보는 **블로그 · 카페 글에 유용한 것이 많다.** 내용이 풍부하고 실용적이면 쓴다 |
| 중요한 것 | 출처가 어디냐가 아니라 **내용이 내 스타일과 맞느냐** |

**스타일을 적는 세 칸 (이름 고정)**

```text
Preferred            좋아하는 것          예) 대표 유명 관광지, 액티비티
Not preferred        싫어하는 것          예) 박물관은 지루해서 싫음
Detailed preference  세부 사정            예) 가족 여행, 사진 많이 남기고 싶음
```

> 세 칸 이름은 고정입니다. 다만 **한 칸에 몇 줄을 쓸지는 자유**입니다. 원하는 만큼 늘려도 됩니다.

## 읽기 4 — 내가 결정할 질문

<!-- FIXED:BEGIN -->

| 결정 ID | 질문 | 이 값이 바꾸는 것 |
| --- | --- | --- |

**쉬운 선택지**

| 결정 ID | A | B | C | 권장 |
| --- | --- | --- | --- | --- |
| `D-여행입력` | 베트남 · 5일 | 일본 · 4일 | 직접 적기 | **A** (정보가 많아 루프가 잘 굴러감) |
| `D-취향분류` | 2갈래 (좋음 / 싫음) | 3갈래 (좋음 / 싫음 / 세부 사정) | 3갈래 + 내가 갈래 추가 | **B** |
| `D-도시선정기준` | 1등 유명도 · 2등 내 취향 | 1등 내 취향 · 2등 치안·교통 | 1등 내 취향 · 2등 유명도 · 3등 교통 | **B** |

> `D-도시선정기준`에서 A를 고르면 누구나 아는 도시가 뽑힙니다.
> B를 고르면 **내 취향에 맞는 도시**가 먼저 뽑히고, 그 이유가 화면에 적힙니다.
