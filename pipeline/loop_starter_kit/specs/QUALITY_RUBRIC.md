# 정성 규율 10가지 — 루프 C가 매 회차 점검하는 것

이 문서는 **직접 고르는 문서가 아닙니다.** 킷이 정해 둔 고정 규율입니다.
`MASTER_SPEC.md`의 `quality_contract.rules`가 여기 있는 ID를 그대로 가리킵니다.

| 문서 규칙 | 결정 장부 | 화면 계약 |
| --- | --- | --- |
| [00_INDEX](00_INDEX.md) | [00_DECISION_LOG](00_DECISION_LOG.md) | [02_PAGE_DESIGN](02_PAGE_DESIGN.md) |

## 1. 왜 이 문서가 있나

루프 A와 루프 B는 **셀 수 있는 것**만 봅니다.

```text
루프 A  개수 · 글자 수 · 서로 다른 출처 · 중복 비율 · 이미지 검증 기록
루프 B  칸이 있는가 · 눌리는가 · 모은 내용이 들어갔는가
```

둘 다 통과했는데도 남는 것이 있습니다.

```text
하루 블록이 전부 명소, 이동·식사가 없다   → 계약은 통과. 사람은 즉시 안다
세 도시의 계획이 이름만 바꾼 같은 글이다  → 계약은 통과. 읽으면 허탈하다
"왜 넣었는지"가 내가 쓴 말과 안 이어진다  → 계약은 통과. 내 여행이 아니다
```

**루프 C는 이 영역만 봅니다.** 세는 것으로 잡히는 결함은 루프 A·B의 몫이며,
루프 C가 그것을 대신 잡으려 하면 3회뿐인 예산을 거기서 다 씁니다.

## 2. 규율 10가지

| ID | 무엇을 보나 | 위반이면 무엇을 고치나 |
| --- | --- | --- |
| `Q-반복금지` | 같은 문장·문형을 복제해 분량을 채우지 않았는가 | 복제 줄을 실제 내용으로 교체 |
| `Q-취향연결` | "왜 넣었는가"가 `USER_REQUEST.md` 원문의 표현과 이어지는가 | 원문 표현을 인용해 다시 씀 |
| `Q-뺀이유` | 도시마다 **뺀 것과 그 이유**가 실재하는 이름으로 2건 이상 있는가 | 실제 후보를 조사해 뺀 이유를 추가 |
| `Q-상세삼요소` | 관광지 상세에 **무엇을 보나 · 실용 정보 · 취향 연결** 셋이 다 있는가 | 빠진 요소를 보강 |
| `Q-일정현실성` | 하루가 물리적으로 가능한가 — 시간이 이어지고 이동·식사·휴식이 있는가 | 블록 시간을 다시 배치 |
| `Q-근거일치` | 본문의 주장이 `items[]`에 실제로 있는가. 지어낸 수치가 없는가 | 근거 없는 문장을 삭제하거나 근거를 보강 |
| `Q-도시차별화` | 도시별 계획이 서로 구별되는가. 이름만 바꾼 같은 글이 아닌가 | 그 도시에서만 가능한 내용으로 다시 씀 |
| `Q-동행반영` | 내가 쓴 동행·상황 조건이 실제 선택에 반영되었는가 | 조건에 맞지 않는 항목을 교체 |
| `Q-실용누락` | 예약 필요 여부 · 이동 수단 · 대략 비용이 빠지지 않았는가 | 누락된 실용 정보를 조사해 추가 |
| `Q-계약무결` | 이번 회차 수정이 이름표 · 출처 링크 · 이미지 주소를 훼손하지 않았는가 | 훼손된 부분을 되돌림 |

> `Q-계약무결`만 성격이 다릅니다. 나머지 아홉이 **결과물을 좋게 만드는 규율**이라면,
> 이것은 **좋게 만들다가 계약을 깨뜨리지 않았는지** 보는 규율입니다.

## 3. 회차마다 렌즈가 다르다

**매 회차 10개를 전부 판정합니다.** 다만 그 회차에 **고치는 우선순위**가 다릅니다.

| 회차 | 렌즈 | 그 회차의 초점 |
| --- | --- | --- |
| **1** | 내용이 실한가 | `Q-반복금지` `Q-취향연결` `Q-뺀이유` `Q-상세삼요소` |
| **2** | 실행 가능하고 사실인가 | `Q-일정현실성` `Q-근거일치` `Q-도시차별화` `Q-실용누락` |
| **3** | 독자 관점에서 완결인가 | `Q-동행반영` `Q-계약무결` + 앞 두 회차가 되돌아가지 않았는지 |

같은 렌즈로 세 번 보면 **2회차부터 "이상 없음"만 나옵니다.** 그래서 렌즈를 나눕니다.

## 5. 판정기가 보는 것과 보지 않는 것

<div></div>

```text
보지 않는다   글이 좋아졌는가        ← 점수를 매기지 않는다
보지 않는다   품질이 몇 점인가        ← 쓴 사람이 채점하면 판정 독립이 깨진다

본다         3회를 다 돌았는가
본다         회차마다 10개를 전부 판정했는가
본다         위반이라 적은 것을 실제로 고쳤는가
본다         위반이면 어디(where)인지 적었는가
본다         고쳤다면 파일이 실제로 바뀌었는가
본다         고칠 게 없다면 파일이 그대로인가
본다         3회 합쳐 고친 것이 1건 이상인가  ← 한 회차는 무수정이어도 되지만
                                                  3회 전부 0건이면 SHORT → 되물음
본다         회차 끝마다 루프 A·B가 여전히 통과하는가
```

> **품질을 채점하지 않고 절차를 채점합니다.**
> 품질 점수를 종료 조건으로 쓰면 글을 쓴 쪽이 자기 글에 점수를 줍니다.
> 그 순간 조건⑤(판정 독립)가 무너집니다. 그래서 종료 조건은 **"3회를 돌았는가"**입니다.

## 6. 되돌리기 규칙 (가장 중요)

정성 수정이 정량 계약을 깨뜨리면 **그 회차의 수정을 되돌립니다.**

```bash
python scripts/verify_all.py --skip-quality      # 회차 끝마다 반드시
```

`exit 0`이 아니면 그 회차는 완료가 아닙니다. 되돌리고 다시 고칩니다.
이 검사가 없으면 **정성 개선이 정량 계약을 파괴하는 루프**가 됩니다.
