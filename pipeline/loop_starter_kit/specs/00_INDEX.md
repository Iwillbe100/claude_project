# 명세 문서 사용법

STEP 문서는 전부 **같은 8구역**으로 되어 있습니다. 한 번만 익히면 나머지는 똑같습니다.

---

## 1. STEP 지도 — 결정은 전부 합쳐 21개

| STEP | 이름 | 정하는 것 | 결정 수 | 파일 |
| --- | --- | --- | --- | --- |
| 1 | 입력과 취향 | 어디를·며칠·어떤 스타일로 | 3 | [01](01_INPUT_AND_STYLE.md) |
| 2 | 페이지 구성안 | 화면이 어떻게 생겼나 | 3 | [02](02_PAGE_DESIGN.md) |
| 3 | 정보량 카운트 | 몇 개면 충분한가 (숫자만) | 4 | [03](03_INFORMATION_COUNT.md) |
| 4 | 경계·작업·안전 | 어디까지 맡기고 언제 끼어드나 | 3 | [04](04_BOUNDARY_TASKS_SAFETY.md) |
| 5 | 테스트와 검증 | 무엇이 PASS를 판정하나 | 3 | [05](05_TEST_AND_VERIFIER.md) |
| 6 | 반복 방법 | 실패하면 무엇을 하나 | 3 | [06](06_LOOP_ITERATION.md) |
| 7 | 실행 계약 | 무엇이 되면 끝인가 | 2 | [07](07_EXECUTION_CONTRACT.md) |

## 2. 이 실습이 만드는 것

```text
                  ┌─────────────────────────────────────┐
   내가 답한다 ──▶ │  STEP 1~7 명세 (질문 21개)          │
                  └──────────────┬──────────────────────┘
                                 │ 모임
                                 ▼
                  ┌─────────────────────────────────────┐
                  │  MASTER_SPEC.md                     │
                  │    count_contract  숫자로 된 목표    │
                  │    page_contract   화면 그림         │
                  └──────────────┬──────────────────────┘
                                 │ 읽음
                                 ▼
                  ┌─────────────────────────────────────┐
   루프가 돈다 ──▶ │  검사기 (킷이 제공 · 잠겨 있음)      │
                  │    루프 A  정보를 다 모았나          │
                  │    루프 B  화면을 다 채웠나          │
                  │    루프 C  정성 3회를 돌았나         │
                  └──────────────┬──────────────────────┘
                                 ▼
                     output/travel_site.html  (파일 하나)
```

## 3. 루프는 셋이다

```text
   루프 A 정보량 충족 → 루프 B 페이지 완성 → 루프 C 정성 완성도
        └─ 먼저 끝나야 함 ─┴─ 먼저 끝나야 함 ─┘

   각 루프가 끝나면 나에게 되물음이 뜹니다.
   "이만큼 채웠는데 계속할까요, 넘어갈까요?"
```

| 루프 | 끝나는 조건 | 누가 정하나 |
| --- | --- | --- |
| A 정보량 | 검사기 통과 (상한까지) | 교육생 |
| B 페이지 | 검사기 통과 (상한까지) | 교육생 |
| **C 정성** | **정해진 3회를 돌면** | **킷 고정** |

> 정성은 점수로 닫을 수 없습니다. 글을 쓴 쪽이 자기 글에 점수를 주기 때문입니다.
> 그래서 **회차로 닫습니다.** 규율은 [QUALITY_RUBRIC](QUALITY_RUBRIC.md)에 있습니다.

## 4. 읽는 순서 — 모든 STEP이 똑같다

| 번호 | 구역 | 누가 쓰나 | 읽는 법 |
| --- | --- | --- | --- |
| `1` | 이 STEP에서 정하는 것 | 이미 작성됨 | 30초 |
| `2` | 앞에서 물려받은 결정 | Claude가 채움 | 확인만 |
| `3` | 이미 정해 둔 것 | 이미 작성됨 | **훑고 넘어가기** |
| `4` | 내가 결정할 질문 | **고정. 수정 금지** | **여기서만 고민** |
| `5` | 내 답 적기 | **교육생** | 고른 것을 적는다 |
| `6` | Claude가 정리한 결과 | Claude가 채움 | 확인만 |
| `7` | 이 STEP이 끝나면 무엇이 진행되는가 | 이미 작성됨 | **다음에 뭘 할지 여기 있다** |
| `8` | 완료 확인과 다음 명령 | 함께 확인 | 체크리스트 |

> **고민할 곳은 `읽기 4` 하나뿐입니다.** 나머지는 읽거나 확인만 하면 됩니다.

## 5. 결정 ID 읽는 법

이름만 보고 무엇을 정하는지 알 수 있어야 합니다.

```text
좋음   D-도시수        도시를 몇 개 고를지
좋음   TASK-명소수집   관광지를 모으는 작업
나쁨   D-008           무엇을 정했는지 알 수 없다
```

| 종류 | 형식 | 규칙 |
| --- | --- | --- |
| 결정 | `D-이름` | 한글 2~16자. 숫자만 쓰지 않는다 |
| 작업 | `TASK-이름` | 이름이 곧 하는 일 |
| 테스트 | `TEST-이름` | **검사하는 루프의 이름**을 쓴다 |

**테스트 이름이 작업 이름과 다른 이유**

```text
작업은 7개, 내가 고르는 채점표는 2개입니다.

  루프 A   TASK-입력읽기 · TASK-국가정보 · TASK-도시선정
           TASK-명소수집 · TASK-일정수집        ──▶  TEST-정보량
  루프 B   TASK-페이지생성 · TASK-기능점검       ──▶  TEST-페이지
  루프 C   TASK-정성점검 (킷 고정)              ──▶  킷 고정 판정기

작업마다 채점표를 따로 두면 7개를 관리해야 합니다.
판정 기준이 하나면 채점표도 하나입니다. 그래서 루프마다 하나씩 붙입니다.
루프 C의 판정기는 깐깐함을 고르지 않으므로 결정이 늘지 않습니다.
```

문서 안에서 ID는 **항상 백틱으로 감쌉니다.** 그래야 스크립트가 찾습니다.

## 6. 문서 안의 표시(마커)

| 마커 | 뜻 | 누가 고치나 |
| --- | --- | --- |
| `FIXED` | 고정 질문. **문장을 바꾸지 않는다** | 아무도 |
| `ANSWERS` | 교육생이 답하는 칸 | 교육생 |
| `PROJECT` | 결정이 반영되는 칸 | Claude |
| `MACHINE` | 스크립트가 읽는 JSON | Claude |
| `STATUS` | 현재 상태 한 줄 | Claude |
| `EXAMPLE` | 예시. 검사에서 제외 | — |

`(미작성)`이 남아 있으면 아직 답하지 않은 것입니다.

## 7. 상태값 6가지

```text
DRAFT             아직 시작 안 함
IN_PROGRESS       진행 중
READY_FOR_REVIEW  검토 요청
APPROVED          승인됨
NEEDS_REVIEW      앞 결정이 바뀌어 다시 볼 것
BLOCKED           막힘
```

**필수 결정이 비어 있으면 `APPROVED`로 바꾸지 않습니다.**

## 8. 진행하는 법

```text
STEP 1 진행해줘      ← 이렇게만 말하면 됩니다
```

Claude가 질문을 **2~3개씩** 보여 주고, 답을 받아 읽기 6을 채우고,
[결정 장부](00_DECISION_LOG.md)에 기록한 뒤 뒤 STEP의 물려받은 값을 갱신합니다.

**STEP 7이 끝나면** [결정 장부](00_DECISION_LOG.md)의 **5번**에
내가 고른 21개가 만든 **루프 구조도**가 그림으로 그려집니다.
"이 답들이 합쳐지면 무엇이 되는가"를 거기서 한눈에 볼 수 있습니다.

## 9. 확인 명령

| 명령 | 무엇을 보나 |
| --- | --- |
| `python scripts/validate_specs.py --step 3` | 문서 구조가 맞는가 (한 STEP) |
| `python scripts/validate_specs.py` | 문서 구조가 맞는가 (전체) |
| `python scripts/check_loop_readiness.py` | 루프를 시작해도 되는가 |
| `python scripts/verify_all.py` | 루프가 끝났는가 — 세 루프 전부 (루프 실행 중에만) |
| `python scripts/verify_all.py --skip-quality` | 정성 회차 중 되돌아감 확인 |

| 결과 | 뜻 |
| --- | --- |
| `PASS` / `READY` / exit 0 | 이상 없음 |
| `NOT_READY` / `SHORT` / exit 2 | 아직 안 한 것이 있음 — **정상** |
| `ERROR` / exit 1 | 파일이 깨짐 — 고쳐야 함 |

## 10. 검사기는 왜 킷이 미리 만들어 두었나

```text
AI가 채점표를 직접 만들면
    "칸이 3개 이상이면 통과" 라고 써 놓고
    칸 3개짜리 결과물을 만들어서
    스스로 통과시킵니다.

실제로 이 일이 있었습니다. 명세는 13칸을 요구했는데
AI가 만든 채점표는 3칸만 셌고, 검사는 통과했습니다.
```

그래서 `scripts/**` 는 킷이 만들어 넣고 **수정 금지**로 잠급니다.
교육생이 정하는 것은 **얼마나 깐깐하게 볼지**뿐입니다 (STEP 5).

## 11. 이미 승인한 결정을 바꾸고 싶다면

조용히 덮어쓰지 않습니다.

```text
"D-도시수를 3개에서 5개로 바꾸고 싶어"
```

Claude가 영향 범위를 표로 보여 주고, [결정 장부](00_DECISION_LOG.md)에
이전 값·새 값·이유·시각을 남기고, 영향받는 STEP을 `NEEDS_REVIEW`로 바꿉니다.
