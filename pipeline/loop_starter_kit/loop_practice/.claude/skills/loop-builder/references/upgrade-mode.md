# 모드 B — 루프 아키텍처 고도화 절차

`/loop-evaluator`가 쓴 `upgrade/S<n>.md`를 읽고, **루프 아키텍처를 다음 세션 버전으로 올리는** 절차다.

```text
고도화의 대상은 언제나 루프 아키텍처다.
주제 산출물(코드·문서·데이터 본체)을 고치지 않는다. 그것은 다음 /loop-run 의 일이다.
```

---

## STEP 1 — 현재 상태를 확인한다

```bash
sed -n '1,20p' ARCHITECTURE.md      # 현재 세션 확인
ls upgrade/                          # 고도화 보고서 목록
cat memory/S01/INDEX.md              # 세션이 실제로 어떻게 끝났는지
ls evidence/S01/                     # 회차 수와 증거 존재 여부
```

| 상황 | 처리 |
| --- | --- |
| `upgrade/<현재세션>.md`가 없다 | `BLOCKED`. "먼저 `/loop-evaluator`로 결과를 검토해 주세요"라고 안내하고 멈춘다 |
| 세션에 회차가 0개다 | 교육생에게 알린다. "아직 한 번도 돌지 않은 아키텍처입니다. 그래도 고도화할까요?" |
| 보고서 판정이 `CANNOT_VERIFY` | 고도화 대신 **검증 가능성을 높이는 방향**(게이트를 실행 가능한 형태로 바꾸기)으로 설계한다 |
| 고도화 지점이 0개다 | 아키텍처를 바꾸지 않는다. "현재 설계로 한 세션 더 돌려 보는 것"을 권한다 |

---

## STEP 2 — 고도화 보고서를 읽는다

`upgrade/S<n>.md`에서 특히 아래 두 절을 정확히 읽는다.

| 절 | 무엇을 얻는가 |
| --- | --- |
| `## 4. 발견한 문제` | 문제별 **근거 파일 경로**와 확인 수준 |
| `## 6. 아키텍처 변경 지시서` | 어느 블록을 어떻게 바꿔야 하는지 표 |

**보고서를 그대로 믿지 않는다.** 각 항목의 근거 파일을 최소 1개는 직접 열어 확인한다.

```bash
cat evidence/S01/run-02/manifest.json
sed -n '1,60p' memory/S01/run-02.md
```

근거가 실제와 다르면 그 항목은 `[거절]`하고 이유를 남긴다.

---

## STEP 3 — 지점별로 판단한다

각 고도화 지점을 넷 중 하나로 처리한다. **판단 없이 전부 채택하지 않는다.**

| 판단 | 언제 | 기록할 것 |
| --- | --- | --- |
| `채택` | 근거가 확인되고, 교육생 8문항 범위 안이고, 한 단계 안에서 반영 가능 | 어느 블록이 어떻게 바뀌는가 |
| `수정 채택` | 문제는 맞지만 제안된 해결책이 과하거나 범위를 벗어남 | 왜 다르게 반영했는가 |
| `보류` | 지금 세션 목표보다 앞선 고도화 | 언제 다시 볼 것인가 |
| `거절` | 근거가 실제와 다름 / 교육생이 명시적으로 범위 밖이라 한 것 / 아키텍처가 아니라 산출물 문제 | 거절 이유 |

### 판단 기준 4개

```text
1. 근거가 있는가        - evidence/ 또는 memory/ 의 실제 파일로 확인되는가
2. 범위 안인가          - 교육생 8문항 답변의 목적·범위를 벗어나지 않는가
3. 한 단계인가          - 이번 세션에 한 칸만 올리는 변경인가 (두 칸을 한 번에 올리지 않는다)
4. 루프 구조 문제인가   - 산출물 품질 문제라면 아키텍처가 아니라 다음 회차가 해결할 일이다
```

### 아키텍처 문제 vs 산출물 문제 구분

| 보고서의 지적 | 실제 성격 | 처리 |
| --- | --- | --- |
| "게이트가 이 조건을 검사하지 않아 깨져도 통과한다" | 아키텍처(블록 C) | 채택 — 게이트 추가 |
| "실패했는데 memory에 원인이 '실패'만 적혀 있다" | 아키텍처(블록 E) | 채택 — 기록 항목 강화 |
| "상한에 걸렸는데 성공처럼 보고됐다" | 아키텍처(블록 G) | 채택 — 판정 규칙 명확화 |
| "증거가 사람이 못 읽는 형식뿐이다" | 아키텍처(블록 D) | 채택 — 증거 타입 보강 |
| "산출물의 특정 값이 틀렸다" | 산출물 | 거절 — 다음 `/loop-run`이 고칠 일 |
| "코드 스타일이 일관되지 않다" | 산출물 | 거절 또는 게이트로 승격할지 판단 |

## STEP 4 — 9블록에 반영한다

채택한 항목을 블록별로 모아서 한 번에 반영한다.

| 자주 바뀌는 블록 | 전형적 변경 |
| --- | --- |
| **C 게이트** | 게이트 추가, 통과 기준을 관측 가능한 값으로 재작성, 실행 명령 구체화 |
| **D 증거** | 증거 타입 추가(기계 판독/사람 확인 균형), 파일명 규칙 정리, manifest 필드 보강 |
| **E 메모리** | 기록 항목 추가(관측값 필수화 등), INDEX 갱신 규칙 강화 |
| **F 재시도** | 실패 유형 세분화, 반복 실패 시 ESCALATE 규칙 추가 |
| **G 종료** | 상한 조정, EXHAUSTED/BLOCKED 표기 명확화 |
| **B 파이프라인** | 1회 범위 축소·확대 (범위가 너무 커서 회차가 안 끝났을 때) |
| **H 불변** | 불변 대상 추가 (기준 완화가 실제로 일어났을 때) |

반영 규칙:

```text
O 바뀐 부분만 고친다. 문서를 통째로 다시 쓰지 않는다
O 게이트 ID는 이어서 붙인다 (G4 다음은 G5). 기존 ID 의미를 바꾸지 않는다
O 완료 정의를 줄이지 않는다. 늘리는 것은 근거가 있을 때만
O 표 형식과 절 순서를 유지한다 — 세션 간 비교가 가능해야 한다

X 보고서 문장을 그대로 복사해 붙인다
X 지적되지 않은 부분까지 "겸사겸사" 손본다
X 이전 세션 기록(evidence/ memory/ upgrade/)을 수정하거나 지운다
```

### `ARCHITECTURE.md` 헤더와 이력 갱신

```markdown
| 현재 세션 | S02 |
| 설계 근거 | 교육생 8문항 답변 + upgrade/S01.md 반영 |

## 세션 변경 이력

| 세션 | 날짜 | 반영 근거 | 바뀐 블록 | 변경 요약 |
| --- | --- | --- | --- | --- |
| S01 | … | 최초 8문항 | 전체 | 최초 설계 |
| S02 | … | `upgrade/S01.md` 문제 1·2 | C, E | G5 추가 / 메모리 관측값 필수화 / 문제 3은 보류(이유) |
```

**보류·거절 항목도 이력에 남긴다.** 교육생이 "왜 반영 안 됐지?"를 파일에서 확인할 수 있어야 한다.

---

## STEP 5 — `loop-run` 스킬을 다시 생성한다

바뀐 블록이 `loop-run`의 어느 섹션에 영향을 주는지 확인하고 갱신한다.

| 바뀐 블록 | `loop-run`에서 고칠 섹션 |
| --- | --- |
| A | 0절 요약, 6절 SUCCESS 조건 |
| B | 2절 1회 루프 절차 |
| C | 3절 게이트 표 |
| D | 4절 증거 수집 |
| E | 5절 메모리 기록 |
| F, G | 6절 판정 |
| H, I | 7·8절 금지·불변 |

세션 번호가 올라갔으므로 **경로 문자열을 전부 갱신한다**: `memory/S01/` → `memory/S02/`, `evidence/S01/` → `evidence/S02/`.
생성 후 `references/loop-run-template.md` 3절의 자기 점검을 다시 수행한다.

---

## STEP 6 — 세션을 승격하고 요약한다

```bash
mkdir -p evidence/S02 memory/S02
```

- `memory/S02/INDEX.md`를 새로 만든다 (빈 뼈대 + 헤더의 세션·상한 갱신)
- **이전 세션에서 넘어오는 미해결 항목**이 있으면 `INDEX.md`의 "다음 회차 시작 시 반드시 적용할 것"에 옮겨 적고, 출처를 `upgrade/S01.md` 또는 `memory/S01/INDEX.md`로 표기한다
- `evidence/S01/`, `memory/S01/`, `upgrade/S01.md`는 **그대로 보존한다**

마지막에 `SKILL.md` §11-3 요약 카드를 출력한다. 표에는 채택·수정 채택·보류·거절을 전부 넣는다.

## 자기 점검 (보고 전)

```text
[ ] 고도화 보고서의 모든 지점을 하나도 빠짐없이 판단했는가
[ ] 채택한 항목마다 근거 파일을 실제로 열어 확인했는가
[ ] 보류·거절에 이유를 남겼는가
[ ] 바뀐 블록이 ARCHITECTURE.md 와 loop-run 양쪽에 반영됐는가
[ ] 세션 번호와 경로 문자열이 모두 갱신됐는가
[ ] 이전 세션 기록을 하나도 수정하지 않았는가
[ ] 완료 정의를 임의로 줄이지 않았는가
[ ] 지적되지 않은 부분을 함께 손보지 않았는가
[ ] 터미널 요약이 "핵심만" 담고 있는가 (전문은 ARCHITECTURE.md)
[ ] 상태를 UPGRADED 로 명시했는가
```
