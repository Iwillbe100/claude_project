# ARCHITECTURE.md 작성 템플릿 (9블록)

`/loop-builder`가 프로젝트 루트에 `ARCHITECTURE.md`를 만들 때 쓰는 양식이다.
**아래 구조를 그대로 쓰고, `<...>` 부분만 주제 언어로 채운다.** 블록을 빼거나 순서를 바꾸지 않는다.

작성 원칙 4가지:

```text
1. 교육생이 읽고 "내 아이디어가 루프가 됐다"고 알아볼 수 있어야 한다
2. /loop-run 이 이 문서만 보고도 회차를 돌릴 수 있어야 한다
3. /loop-evaluator 가 이 문서를 기준으로 실제 결과를 대조할 수 있어야 한다
4. 모든 판정 기준은 관측 가능한 값으로 쓴다 (감각 표현 금지)
```

---

## 블록 B. 1회 루프 파이프라인

한 회차는 아래 STEP을 **순서대로 한 번** 수행한다. 회차 중간에 순서를 바꾸지 않는다.

| STEP | 이름 | 하는 일 | 산출 | 실패 시 |
| --- | --- | --- | --- | --- |
| 1 | 메모리 로드 | `memory/<세션>/INDEX.md`와 직전 `run-*.md`를 읽고 이번 회차 목표를 확정한다 | 회차 목표 | BLOCKED |
| 2 | <작업 1> | <주제 맞춤 구체 동작> | <산출물> | RETRY |
| 3 | <작업 2> | | | |
| 4 | 검증 | 게이트 G1~Gn을 순서대로 실행한다 | 게이트 결과 | 게이트별 규칙 |
| 5 | 증거 저장 | `evidence/<세션>/run-<n>/`에 증거와 `manifest.json`을 남긴다 | 증거 파일 | BLOCKED |
| 6 | 메모리 기록 | `memory/<세션>/run-<n>.md` 작성 + `INDEX.md` 갱신 | 회차 기록 | BLOCKED |
| 7 | 판정 | 블록 F·G 규칙으로 상태를 정한다 | 판정 | — |

**1회 루프의 범위 (교육생 3번 답변)**
<한 회차에 여기까지만 한다 — 경계를 한 문장으로>

**한 회차에서 하지 않는 것**
- 실패 원인과 무관한 부분을 함께 고치지 않는다
- 새 기능을 추가해 문제를 우회하지 않는다

## 블록 C. 검증 게이트

게이트는 **증거를 만들어 내는 검사**다. 통과 기준은 사람이 아니라 값이 정한다.

| ID | 무엇을 검증하는가 | 실행 명령 / 관찰 절차 | 통과 기준 | 증거 | 실패 시 |
| --- | --- | --- | --- | --- | --- |
| G1 | <...> | `<정확한 명령>` | <종료코드 0 / 실패 0건 / 값 범위> | E1 | RETRY |
| G2 | <...> | <관찰 절차 3줄 이내> | <...> | E2 | RETRY |
| G3 | <...> | | | E3 | ESCALATE |

**게이트 실행 순서**: G1 → G2 → … (앞 게이트가 FAIL이면 뒤 게이트는 `SKIP`으로 기록하고 원인 분석으로 넘어간다)

**환경상 실행할 수 없는 게이트**
| ID | 실행 불가 조건 | 그때의 처리 |
| --- | --- | --- |
| G3 | <예: 브라우저 조작 도구 없음> | `BLOCKED`으로 기록하고 수행한 척하지 않는다 |

## 블록 D. 증거 규약

| ID | 증명하는 것 | 파일명 규칙 | 데이터 타입 | 수집 시점 | 연결 게이트 |
| --- | --- | --- | --- | --- | --- |
| E1 | <...> | `g1-<...>.txt` | 실행 로그 전문 (txt) | G1 직후 | G1 |
| E2 | <...> | `g2-<...>.json` | 구조화 결과 (json) | G2 직후 | G2 |
| E3 | <...> | `g3-<...>.png` | 화면 캡처 (png) | G3 직후 | G3 |

**저장 위치**: `evidence/<세션>/run-<회차 2자리>/`
**필수 동반 파일**: 같은 폴더의 `manifest.json` (스펙은 `evidence/README.md`)

**증거 4원칙**
1. 기계 판독용(json/csv) 최소 1개
2. 사람 확인용(md/txt/png) 최소 1개
3. 원본 그대로 저장 — 요약본으로 대체하지 않는다
4. 재현 정보 포함 — 어떤 명령·입력으로 나왔는지 함께 기록

## 블록 E. 메모리 규약

**회차 기록**: `memory/<세션>/run-<회차>.md` — 6절 고정 양식 (`memory/README.md` 참조)
**누적 메모리**: `memory/<세션>/INDEX.md` — 회차 요약 / 미해결 항목 / 반복 실패 / 다음 회차 필수 반영

**다음 회차로 반드시 넘기는 것** (교육생 5번 답변 기준)

| # | 넘기는 정보 | 어디에 적는가 | 다음 회차가 어떻게 쓰는가 |
| --- | --- | --- | --- |
| M1 | 실패한 게이트 ID와 실제 관측값 | `run-<n>.md` 2절 | 같은 게이트를 최우선 목표로 삼는다 |
| M2 | 실패 원인 (직접 원인 + 근본 원인 추정) | `run-<n>.md` 3절 | 같은 접근을 반복하지 않는다 |
| M3 | 다음 회차 조치 목록 | `run-<n>.md` 5절 | STEP 1에서 이번 회차 목표로 확정한다 |
| M4 | 이미 해결된 항목 | `INDEX.md` | 다시 건드리지 않는다 |

**금지**: 로그 전문을 메모리에 복사해 붙이는 것. 메모리는 판단에 필요한 것만 담고, 원본은 `evidence/`를 링크한다.

## 블록 F. 재시도·분기 규칙

| 실패 유형 | 예시 | 다음 행동 |
| --- | --- | --- |
| 원인이 명확하고 이번 권한으로 고칠 수 있음 | 게이트 기준 미달, 로직 오류 | `RETRY` — 실패 원인과 직접 관련된 부분만 수정 |
| 환경이 없어 검증 자체가 불가 | 런타임 없음, 도구 없음, 파일 접근 불가 | `BLOCKED` — 재시도하지 않고 사용자에게 알린다 |
| 기준과 요구사항이 충돌 | 게이트가 요구사항과 모순 | `ESCALATE` — 아키텍처 문제이므로 멈추고 보고 |
| 같은 게이트가 2회 연속 같은 원인으로 실패 | — | `ESCALATE` — 접근 자체가 틀렸을 가능성 |
| 상한 도달 | 회차 = 반복 상한 | `EXHAUSTED` |

**재시도 범위 제한**: 실패한 게이트와 직접 관련된 부분만 수정한다. 관련 없는 파일을 함께 바꾸면 무엇이 효과가 있었는지 알 수 없다.

## 블록 G. 종료 조건과 반복 상한

| 상태 | 조건 | 그다음 |
| --- | --- | --- |
| `SUCCESS` | 게이트 G1~Gn 전부 PASS + 완료 정의 D1~Dn 전부 충족 + 증거·메모리 기록 완료 | 즉시 종료. 상한을 채우지 않는다 |
| `RETRY` | 실패 + 원인 식별 + 수정 가능 + 회차 < 상한 | 다음 회차 |
| `EXHAUSTED` | 회차 = 상한 + 미충족 조건 존재 | 종료하고 남은 항목을 보고 |
| `BLOCKED` | 환경 문제로 검증 불가 | 종료하고 필요한 것을 요청 |
| `ESCALATE` | 아키텍처·기준 충돌, 사용자 판단 필요 | 종료하고 선택지를 제시 |

**반복 상한**: n 회 (교육생 6번 답변)
**현재 회차 계산**: `memory/<세션>/run-*.md` 파일 개수 + 1

## 블록 H. 불변 조건과 수정 허용 범위

**절대 바꿀 수 없는 것 (불변)**

| # | 불변 대상 | 이유 |
| --- | --- | --- |
| H1 | 블록 C의 게이트 목록·통과 기준·임계값 | 기준을 낮춰 통과시키는 것을 막는다 |
| H2 | 블록 A의 완료 정의 | 목표를 줄여 성공으로 만드는 것을 막는다 |
| H3 | 이미 저장된 `evidence/`·`memory/` 파일 | 기록 위조 방지 |
| H4 | `ARCHITECTURE.md` 자체 | 아키텍처 변경은 `/loop-builder`만 한다 |
| H5 | <교육생 7번 답변의 고정 대상> | |

**수정해도 되는 것**

| # | 대상 | 조건 |
| --- | --- | --- |
| W1 | <주제 산출물 파일> | 실패한 게이트와 직접 관련된 부분만 |
| W2 | 새 `evidence/<세션>/run-<n>/` 폴더 | 추가만, 덮어쓰기 금지 |

**불변 조건을 건드려야 한다고 판단되면 수정하지 말고 `ESCALATE` 한다.**

## 블록 I. 역할 경계

## 채울 때 자주 틀리는 것

| 나쁜 작성 | 왜 문제인가 | 고친 작성 |
| --- | --- | --- |
| 게이트 기준: "정상 동작하면 통과" | 누가 봐도 다르게 판단한다 | "종료코드 0이고 실패 케이스 0건이면 통과" |
| 실행 명령: "테스트를 돌린다" | `/loop-run`이 무엇을 칠지 모른다 | "`npm test -- --reporter=json` 출력을 저장한다" |
| 증거: "결과를 남긴다" | 파일명·타입이 없어 평가할 수 없다 | "`g2-result.json` — 게이트별 pass/fail과 관측값" |
| 완료 정의: "잘 만들어진다" | 종료 판단이 불가능하다 | "D1~D4가 모두 PASS이고 미해결 항목이 0건" |
| 불변 조건 비움 | 기준을 낮춰 통과하는 사고를 못 막는다 | H1~H3 기본 불변 3종을 항상 넣는다 |
| 블록을 5개로 줄임 | 평가·고도화가 대조할 기준을 잃는다 | 9블록을 모두 채운다 (해당 없으면 "해당 없음 + 이유") |
