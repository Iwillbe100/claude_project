# 증거(evidence) · 메모리(memory) · 고도화(upgrade) 기록 규약

`/loop-builder`가 설계 시 이 규약대로 폴더와 README, 양식을 만든다.
`/loop-run`은 이 규약대로 기록하고, `/loop-evaluator`는 이 규약대로 읽는다.

**세 폴더의 역할이 다르다.**

| 폴더 | 무엇을 담는가 | 누가 쓰는가 | 누가 읽는가 |
| --- | --- | --- | --- |
| `evidence/` | 판정의 **원본 근거** (실행 로그, 결과 데이터, 화면 캡처) | `/loop-run` | `/loop-evaluator`, 교육생 |
| `memory/` | 회차의 **해석과 학습** (달성/미달성, 원인, 다음 조치) | `/loop-run` | 다음 회차 `/loop-run`, `/loop-evaluator` |
| `upgrade/` | 세션의 **고도화 지시** (문제, 근거, 해결책) | `/loop-evaluator` | 교육생, `/loop-builder` |

> 한 줄로: **evidence = 무슨 일이 있었나(사실) / memory = 왜 그랬고 다음에 뭘 할까(판단) / upgrade = 구조를 어떻게 바꿀까(설계)**

---

## 1. 폴더 구조

```text
evidence/
├── README.md                 <- 이 주제의 증거 규약 (loop-builder가 생성)
└── S01/
    ├── run-01/
    │   ├── manifest.json     <- 필수. 이 회차의 증거 목록 + 게이트 판정
    │   ├── g1-<이름>.txt
    │   ├── g2-<이름>.json
    │   └── g3-<이름>.png
    └── run-02/
        └── ...

memory/
├── README.md                 <- 이 주제의 메모리 규약 (loop-builder가 생성)
└── S01/
    ├── INDEX.md              <- 누적 메모리. 다음 회차가 가장 먼저 읽는다
    ├── run-01.md
    └── run-02.md

upgrade/
├── README.md                 <- 고도화 보고서 규약 (loop-builder가 생성)
└── S01.md                    <- 세션당 단 하나 (loop-evaluator가 생성)
```

**명명 규칙**
- 세션: `S01`, `S02`, … (2자리 고정)
- 회차: `run-01`, `run-02`, … (2자리 고정)
- 증거 파일: `<게이트ID 소문자>-<내용>.<확장자>` 예) `g2-gate-result.json`
- 덮어쓰기 금지. 같은 회차를 다시 돌릴 일이 생기면 새 회차 번호를 쓴다.

## 2. 주제 유형별 증거 타입 — 여기서 골라 조합한다

`/loop-builder`는 교육생 주제가 어느 줄에 가까운지 판단하고, **기계 판독 1개 + 사람 확인 1개**를 최소로 조합한다.

| 주제 유형 | 기계 판독용 (필수 1) | 사람 확인용 (필수 1) | 있으면 좋은 것 |
| --- | --- | --- | --- |
| 코드 / 라이브러리 | 테스트 결과 `.json`, 커버리지 `.json` | 실행 로그 전문 `.txt` | 변경 diff `.patch` |
| 웹·앱·게임 UI | 상태 덤프 `.json`, 게이트 결과 `.json` | 화면 캡처 `.png`, 조작 로그 `.txt` | 입력 재생 로그 `.jsonl` |
| 데이터 분석 | 지표 `.json`, 결과 테이블 `.csv` | 차트 `.png`, 요약 `.md` | 사용한 쿼리·스크립트 사본 |
| 문서 / 글쓰기 | 체크리스트 결과 `.json`, 항목 대조표 `.csv` | 산출물 스냅샷 `.md` | 이전 버전 diff `.md` |
| 리서치 / 조사 | 출처 목록 `.csv` (URL·접근일·인용문) | 근거 발췌 `.md` | 상충 정보 정리 `.md` |
| 자동화 / 운영 스크립트 | 종료코드·소요시간 `.json` | 실행 로그 `.log` | 실행 전후 상태 `.json` |
| 기획 / 설계 산출물 | 요구사항 충족 표 `.csv` | 설계 문서 스냅샷 `.md` | 결정 근거 `.md` |
| 학습 / 연습 기록 | 문항별 정오 `.json` | 풀이 과정 `.md` | 오답 유형 집계 `.csv` |

**주제가 위 표에 없으면**: "이 주제에서 나중에 '정말 됐는지' 의심받을 때 무엇을 보여 주면 끝나는가"를 묻고, 그 산출물을 증거로 정한다.

### 증거 4원칙 (모든 주제 공통)

```text
1. 기계 판독용 최소 1개 (.json/.csv)  - 평가자가 수치를 자동 대조할 수 있어야 한다
2. 사람 확인용 최소 1개 (.md/.txt/.png)
3. 원본 그대로                        - 로그는 전문 저장. 요약본으로 대체하지 않는다
4. 재현 정보 포함                     - 어떤 명령·입력·시각의 결과인지 파일 안이나 manifest에 남긴다
```

### 증거로 인정하지 않는 것

```text
X "통과했습니다" 라는 문장만 있는 파일        - 관측값이 없다
X 실행하지 않고 예상해서 쓴 결과              - 위조다
X 원본 로그를 지우고 남긴 3줄 요약            - 재검증이 불가능하다
X 어떤 게이트와 연결되는지 알 수 없는 파일     - manifest에 매핑이 없으면 증거가 아니다
```

## 3. `manifest.json` 스펙 (필수)

회차 폴더마다 정확히 하나. `/loop-evaluator`가 가장 먼저 읽는 파일이다.

```json
{
  "session": "S01",
  "run": 1,
  "started_at": "2026-01-01T10:00:00+09:00",
  "ended_at": "2026-01-01T10:12:00+09:00",
  "goal": "이번 회차에서 달성하려 한 것 한 줄",
  "carried_from_previous": ["직전 회차에서 넘겨받아 이번에 반영한 조치"],
  "gates": [
    {
      "id": "G1",
      "name": "게이트 이름",
      "command": "실제로 실행한 명령 또는 관찰 절차",
      "result": "PASS",
      "observed": "관측값 (숫자나 짧은 사실)",
      "threshold": "통과 기준",
      "evidence": ["g1-run-log.txt"],
      "note": ""
    },
    {
      "id": "G2",
      "name": "",
      "command": "",
      "result": "FAIL",
      "observed": "",
      "threshold": "",
      "evidence": ["g2-gate-result.json"],
      "note": "실패 요약 한 줄"
    }
  ],
  "artifacts": ["이번 회차에 만들거나 바꾼 산출물 경로"],
  "verdict": "RETRY",
  "unmet": ["아직 충족하지 못한 완료 정의 ID"],
  "next_actions": ["다음 회차에 할 일"]
}
```

| 필드 | 규칙 |
| --- | --- |
| `result` | `PASS` / `FAIL` / `SKIP` / `BLOCKED` 넷만 사용 |
| `verdict` | `SUCCESS` / `RETRY` / `BLOCKED` / `EXHAUSTED` / `ESCALATE` 다섯만 사용 |
| `evidence` | 같은 폴더의 실제 파일명. **없는 파일을 적지 않는다** |
| `observed` | 반드시 채운다. 비어 있으면 그 게이트는 근거 없는 판정이다 |
| `carried_from_previous` | 회차 1에서는 빈 배열 |

## 4. 회차 메모리 양식 — `memory/S01/run-01.md`

**6절 고정.** 절을 빼거나 순서를 바꾸지 않는다. 모든 회차가 같은 모양이어야 비교가 된다.

```markdown
# S01 / Run 01

| 항목 | 값 |
| --- | --- |
| 일시 | YYYY-MM-DD HH:MM |
| 회차 목표 | <한 줄> |
| 판정 | SUCCESS / RETRY / BLOCKED / EXHAUSTED / ESCALATE |
| 회차 | 1 / 5 (사용 / 상한) |
| 증거 | `evidence/S01/run-01/` |

## 1. 달성한 것

| # | 달성 내용 | 근거 파일 | 관측값 |
| --- | --- | --- | --- |
| 1 | <...> | `g1-run-log.txt` | <...> |

## 2. 달성하지 못한 것

| # | 하려던 것 | 어디서 막혔나 | 근거 파일 | 관측값 |
| --- | --- | --- | --- | --- |
| 1 | <...> | G2 | `g2-gate-result.json` | <기대값 vs 실제값> |

## 3. 실패 원인 분석

- **관측 사실**: <증거에서 확인된 것만. 추측을 섞지 않는다>
- **직접 원인**: <바로 이것 때문에 실패했다>
- **근본 원인 추정**: <왜 그렇게 됐는가. 추정이면 "추정"이라고 쓴다>
- **아키텍처상 원인**: <해당 시. 게이트가 없었다 / 범위가 너무 컸다 / 메모리가 부족했다 등>

## 4. 이번 회차에 바꾼 것

| 파일 | 무엇을 바꿨나 | 왜 |
| --- | --- | --- |

## 5. 다음 회차에 반영할 것

| # | 할 일 | 왜 | 무엇으로 확인하나 |
| --- | --- | --- | --- |
| 1 | <...> | <...> | <게이트 ID 또는 관측 기준> |

## 6. 남은 미해결 항목

| # | 내용 | 최초 발견 회차 | 재발 횟수 |
| --- | --- | --- | --- |
```

### 작성 규칙

```text
O 실제로 한 것만 쓴다
O 관측값을 숫자나 사실로 쓴다 ("8/9 통과", "응답 2.4초", "항목 3개 누락")
O 해결된 것과 남은 것을 구분한다
O 증거 파일을 링크한다 (경로를 적어 두면 평가자가 바로 대조한다)

X 로그 전문을 복사해 붙인다      -> evidence/ 를 링크한다
X "테스트 실패" 한 줄로 끝낸다    -> 다음 회차가 같은 실수를 반복한다
X 과거 회차 기록을 통째로 옮긴다  -> INDEX.md 가 그 역할을 한다
X 하지 않은 검증을 했다고 쓴다     -> 위조다
```

## 5. 누적 메모리 — `memory/S01/INDEX.md`

**다음 회차가 가장 먼저 읽는 파일.** 회차가 끝날 때마다 갱신한다(덧붙이기 + 미해결 표 갱신).

```markdown
# S01 누적 메모리

| 항목 | 값 |
| --- | --- |
| 세션 | S01 |
| 아키텍처 | `ARCHITECTURE.md` (S01) |
| 반복 상한 | n 회 |
| 진행 회차 | m / n |
| 현재 상태 | 진행 중 / SUCCESS / EXHAUSTED / BLOCKED / ESCALATE |

## 회차 요약

| 회차 | 목표 | 판정 | 게이트 결과 | 한 줄 요약 |
| --- | --- | --- | --- | --- |
| 1 | <...> | RETRY | G1 P / G2 F / G3 SKIP | <...> |

## 아직 해결되지 않은 항목

| # | 내용 | 최초 발견 | 재발 | 관련 게이트 |
| --- | --- | --- | --- | --- |

## 반복된 실패 (2회 이상 같은 원인)

| # | 내용 | 발생 회차 | 지금까지 시도한 접근 |
| --- | --- | --- | --- |

> 여기에 항목이 생기면 접근 자체를 의심한다. 3회째에는 `ESCALATE`를 검토한다.

## 다음 회차 시작 시 반드시 적용할 것

1. <...>
2. <...>

## 이미 해결되어 다시 건드리지 않을 것

| # | 내용 | 해결 회차 |
| --- | --- | --- |
```

## 6. `evidence/README.md` 생성 양식

`/loop-builder`가 주제에 맞게 채워서 만든다.

```markdown
# 증거 규약 — <주제 이름>

이 폴더에는 루프 판정의 **원본 근거**만 넣는다. 해석과 계획은 `memory/`에 쓴다.

## 저장 위치
`evidence/<세션>/run-<회차>/`  예) `evidence/S01/run-03/`

## 이 주제에서 남기는 증거

| ID | 증명하는 것 | 파일명 | 데이터 타입 | 수집 시점 | 게이트 |
| --- | --- | --- | --- | --- | --- |
| E1 | | | | | G1 |

## manifest.json
회차 폴더마다 하나. 스펙은 `.claude/skills/loop-builder/references/record-spec.md` 3절.

## 규칙
- 원본 그대로 저장 (로그 전문)
- 덮어쓰기 금지, 회차 폴더는 추가만
- 실행하지 않은 결과를 쓰지 않는다
- manifest에 없는 파일은 증거로 인정되지 않는다
```

## 7. `memory/README.md` 생성 양식

```markdown
# 메모리 규약 — <주제 이름>

## 파일
| 파일 | 역할 | 갱신 시점 |
| --- | --- | --- |
| `S01/INDEX.md` | 누적 메모리. 다음 회차가 가장 먼저 읽는다 | 회차마다 |
| `S01/run-<n>.md` | 회차 기록 6절 고정 양식 | 회차 종료 시 1회 |

## 다음 회차로 넘기는 정보
(ARCHITECTURE.md 블록 E의 M1~Mn 표를 여기에 복사)

## 규칙
- 6절 양식을 지킨다. 절을 빼지 않는다
- 관측값은 숫자·사실로 쓴다
- 원본 로그는 복사하지 않고 `evidence/`를 링크한다
- 해결된 것과 남은 것을 구분한다
```

## 8. `upgrade/README.md` 생성 양식

```markdown
# 고도화 보고서 규약

| 항목 | 내용 |
| --- | --- |
| 파일명 | `S01.md`, `S02.md` — **세션당 정확히 하나** |
| 작성 주체 | `/loop-evaluator` |
| 읽는 주체 | 교육생, 그리고 `/loop-builder` (모드 B) |
| 양식 | `.claude/skills/loop-evaluator/references/upgrade-template.md` 고정 |

## 흐름
1. 세션의 루프가 끝난다 (SUCCESS / EXHAUSTED / BLOCKED / ESCALATE)
2. `/loop-evaluator`가 산출물 + `evidence/` + `memory/`를 대조해 `S<n>.md`를 쓴다
3. 교육생이 읽고 무엇을 고칠지 판단한다
4. `/loop-builder`가 "아키텍처 변경 지시서"를 반영해 세션을 올린다

## 규칙
- 세션당 파일 하나. 문제를 나눠 여러 파일로 쓰지 않는다
- 모든 지적에 근거 파일 경로가 붙는다
- 모든 문제에 해결책이 붙는다
- 이전 세션 보고서를 지우거나 덮어쓰지 않는다
```
