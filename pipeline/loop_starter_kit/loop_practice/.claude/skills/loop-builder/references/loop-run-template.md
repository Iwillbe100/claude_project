# `loop-run` 스킬 생성 템플릿

`/loop-builder`가 `.claude/skills/loop-run/SKILL.md`를 만들 때 쓰는 뼈대다.

`loop-run`은 교육생이 **"루프 진행해"** 한마디만 해도 떠서, `ARCHITECTURE.md` 없이도 혼자 1회차를 완주할 수 있어야 한다.
따라서 아키텍처의 게이트·증거·판정 규칙을 **요약하지 말고 실행 가능한 형태로 옮겨 적는다.**

```text
loop-run 은 "실행자"다.
설계하지 않는다. 판단 기준을 바꾸지 않는다. 한 번 호출에 한 회차만 돈다.
```

---

## 1. 프론트매터 — 여기서 틀리면 스킬이 뜨지 않는다

```yaml
---
name: loop-run
description: "<주제 이름> 루프를 한 회차 실행한다. memory/<세션>/INDEX.md로 이전 실패를 먼저 반영하고, <주제 맞춤 작업>을 수행한 뒤 게이트 G1~Gn을 순서대로 검증하고, evidence/<세션>/run-<n>/에 증거와 manifest.json을, memory/<세션>/run-<n>.md에 회차 기록을 남기고 SUCCESS/RETRY/BLOCKED/EXHAUSTED/ESCALATE 중 하나로 판정한다. 교육생이 \"루프 진행해\", \"루프 돌려\", \"다음 회차 진행해\", \"한 바퀴 더\"라고 말하거나 /loop-run으로 호출할 때 사용한다. 루프 아키텍처 설계·고도화(/loop-builder)나 결과 평가·고도화 보고서 작성(/loop-evaluator)에는 사용하지 않는다."
---
```

### 프론트매터 체크리스트

| 항목 | 규칙 | 흔한 실수 |
| --- | --- | --- |
| `name` | `loop-run` 고정. 소문자+하이픈, 폴더명과 동일 | `/loop-run`, `Loop-Run`, `loop run` |
| `description` 시작 | 3인칭 동사로 끝나는 서술문 | "이 스킬은 …입니다" 같은 1인칭·설명체 |
| 주제 키워드 | 교육생 주제의 고유 단어를 반드시 포함 | 일반명사만 써서 다른 스킬과 구분이 안 됨 |
| 발화 트리거 | "루프 진행해" / "루프 돌려" / "다음 회차 진행해" / "한 바퀴 더" 명시 | 트리거 문구 누락 → 교육생이 매번 `/loop-run` 타이핑 |
| 비적용 명시 | 설계·고도화는 `/loop-builder`, 평가는 `/loop-evaluator` | 세 스킬이 서로 겹쳐 잘못 호출됨 |
| 한 줄 | 값에 줄바꿈 금지 | 여러 줄로 쓰면 YAML 파싱 실패 |
| 따옴표 | 값에 콜론+공백, `#`, 따옴표가 있으면 전체를 큰따옴표로 감싸고 내부 따옴표는 `\"`로 이스케이프 | 인용부호 처리 누락 → 파싱 실패 |
| 길이 | 1024자 이내 | |
| 그 외 키 | `name`, `description` 외 다른 키를 임의로 넣지 않는다 | |

**생성 후 확인**: 파일 첫 줄이 `---`, 세 번째 줄 앞뒤로 `name:`과 `description:`이 한 줄씩, 그다음 줄이 `---`인지 눈으로 본다.

## 2. 본문 뼈대 (8개 섹션 고정)

아래를 그대로 쓰고 `<...>`를 주제 내용으로 채운다. **섹션을 빼지 않는다.**

````markdown
# loop-run — <주제 이름> 루프 실행

> 한 번 호출에 **한 회차**만 돈다. 회차가 끝나면 판정을 보고하고 **멈춘다.**
> 아키텍처 원본: `ARCHITECTURE.md` (세션 <S01>)

---

## 0. 이 회차에서 하는 일 (요약)

| 항목 | 값 |
| --- | --- |
| 세션 | S01 |
| 목표 | <블록 A 한 줄> |
| 한 회차 범위 | <블록 B 범위 한 줄> |
| 게이트 | G1 … Gn |
| 반복 상한 | n 회 |
| 현재 회차 계산 | `memory/S01/run-*.md` 개수 + 1 |

---

## 1. 시작 전 필독 — 메모리를 먼저 읽는다

이 단계를 건너뛰면 같은 실패를 반복한다. **항상 먼저 한다.**

```bash
cat memory/S01/INDEX.md
ls memory/S01/run-*.md 2>/dev/null | tail -1 | xargs -r cat
```

읽고 나서 다음을 확정해 교육생에게 한 문단으로 알린다.

- 이번 회차 번호 (= `run-*.md` 개수 + 1)
- `INDEX.md`의 "다음 회차 시작 시 반드시 적용할 것" 항목
- 이번 회차 목표 (직전 회차의 미달성 항목 우선)
- "반복된 실패" 표에 항목이 있으면 접근을 바꾼다는 선언

회차 번호가 **반복 상한을 넘으면** 작업하지 않고 `EXHAUSTED`로 보고하고 멈춘다.

## 2. 1회 루프 절차

| STEP | 하는 일 | 구체 동작 | 완료 조건 |
| --- | --- | --- | --- |
| 1 | 메모리 로드 | 위 1절 | 이번 회차 목표 확정 |
| 2 | <작업 1> | <주제 맞춤 구체 동작> | <...> |
| 3 | <작업 2> | | |
| 4 | 검증 | 3절 게이트를 순서대로 | 전 게이트 결과 확정 |
| 5 | 증거 저장 | 4절 | `manifest.json` 포함 저장 완료 |
| 6 | 메모리 기록 | 5절 | `run-<n>.md` + `INDEX.md` 갱신 |
| 7 | 판정·보고 | 6절 | 상태 1개 보고 후 종료 |

**작업 범위 제한**
- 이번 회차 목표와 직접 관련된 것만 손댄다
- 실패 후 재시도 시, 실패 원인과 무관한 파일을 함께 바꾸지 않는다
- 새 기능을 추가해 실패를 우회하지 않는다

---

## 3. 검증 게이트

순서대로 실행한다. 앞 게이트가 FAIL이면 뒤 게이트는 `SKIP`으로 기록한다.

| ID | 검증 대상 | 실행 명령 / 관찰 절차 | 통과 기준 | 증거 파일 | FAIL 시 |
| --- | --- | --- | --- | --- | --- |
| G1 | <...> | `<명령>` | <관측 가능한 기준> | `g1-<...>.txt` | RETRY |
| G2 | <...> | `<명령>` | <...> | `g2-<...>.json` | RETRY |
| G3 | <...> | <관찰 절차> | <...> | `g3-<...>.png` | ESCALATE |

**실행할 수 없는 게이트**
| ID | 실행 불가 조건 | 처리 |
| --- | --- | --- |
| G3 | <예: 필요한 도구·런타임 없음> | `BLOCKED` 기록. **수행한 척하지 않는다** |

**절대 금지**: 통과시키려고 명령·기준·임계값을 바꾸는 것. 기준이 틀렸다고 판단되면 `ESCALATE`.

---

## 4. 증거 수집

저장 위치: `evidence/S01/run-<회차 2자리>/`

| ID | 파일명 | 데이터 타입 | 내용 | 게이트 |
| --- | --- | --- | --- | --- |
| E1 | `g1-<...>.txt` | 실행 로그 전문 | <...> | G1 |
| E2 | `g2-<...>.json` | 구조화 결과 | <...> | G2 |

**`manifest.json` (필수, 회차 폴더당 하나)**

```json
{
  "session": "S01",
  "run": 1,
  "started_at": "", "ended_at": "",
  "goal": "",
  "carried_from_previous": [],
  "gates": [
    { "id": "G1", "name": "", "command": "", "result": "PASS",
      "observed": "", "threshold": "", "evidence": ["g1-....txt"], "note": "" }
  ],
  "artifacts": [],
  "verdict": "RETRY",
  "unmet": [],
  "next_actions": []
}
```

규칙
- `observed`를 비우지 않는다. 비면 근거 없는 판정이다
- 존재하지 않는 파일을 `evidence`에 적지 않는다
- 로그는 전문 저장. 요약본으로 대체하지 않는다
- 이전 회차 폴더를 덮어쓰지 않는다

## 5. 메모리 기록

`memory/S01/run-<회차>.md` — 6절 고정 양식으로 쓴다.

```markdown
# S01 / Run <n>

| 항목 | 값 |
| --- | --- |
| 일시 | |
| 회차 목표 | |
| 판정 | |
| 회차 | n / N |
| 증거 | `evidence/S01/run-<n>/` |

## 1. 달성한 것
| # | 달성 내용 | 근거 파일 | 관측값 |

## 2. 달성하지 못한 것
| # | 하려던 것 | 어디서 막혔나 | 근거 파일 | 관측값 |

## 3. 실패 원인 분석
- 관측 사실 / 직접 원인 / 근본 원인 추정 / 아키텍처상 원인

## 4. 이번 회차에 바꾼 것
| 파일 | 무엇을 | 왜 |

## 5. 다음 회차에 반영할 것
| # | 할 일 | 왜 | 무엇으로 확인하나 |

## 6. 남은 미해결 항목
| # | 내용 | 최초 발견 회차 | 재발 횟수 |
```

이어서 `memory/S01/INDEX.md`를 갱신한다.
- 회차 요약 표에 한 줄 추가
- 미해결 항목 표 갱신 (해결된 항목은 "이미 해결" 표로 이동)
- 같은 원인이 2회 이상이면 "반복된 실패" 표에 추가
- "다음 회차 시작 시 반드시 적용할 것" 갱신

## 6. 판정과 다음 행동

| 상태 | 조건 | 다음 행동 |
| --- | --- | --- |
| `SUCCESS` | 전 게이트 PASS + 완료 정의 충족 + 증거·메모리 기록 완료 | 즉시 종료. 상한을 채우지 않는다. 교육생에게 `/loop-evaluator` 안내 |
| `RETRY` | 실패 + 원인 식별 + 수정 가능 + 회차 < 상한 | 교육생에게 결과를 보고하고 **멈춘다.** 다음 회차는 교육생이 "루프 진행해"로 시작한다 |
| `EXHAUSTED` | 회차 = 상한 + 미충족 존재 | 종료. 남은 항목과 함께 `/loop-evaluator` 안내 |
| `BLOCKED` | 환경 문제로 검증 불가 | 종료. 무엇이 필요한지 구체적으로 요청 |
| `ESCALATE` | 기준 충돌 / 반복 실패 3회 / 아키텍처 변경 필요 | 종료. 선택지를 제시하고 `/loop-builder` 안내 |

**회차 종료 보고 형식 (터미널, 핵심만)**

```markdown
## 루프 S01 / Run <n> 종료 — <판정>

| 게이트 | 결과 | 관측값 |
| --- | --- | --- |

- **달성**: (1~3줄)
- **미달성**: (1~3줄, 원인 포함)
- **증거**: `evidence/S01/run-<n>/` (파일 k개)
- **기록**: `memory/S01/run-<n>.md`
- **다음**: <다음 회차에 할 일 / 또는 다음 스킬 안내>
```

## 7. 절대 하지 않을 일

```text
X 게이트·기준·임계값을 바꾼다                  -> 기준 충돌이면 ESCALATE
X 실행하지 않은 검증을 통과로 쓴다              -> 증거 위조
X 증거 없이 PASS를 선언한다
X ARCHITECTURE.md 를 수정한다                  -> 아키텍처 변경은 /loop-builder
X upgrade/*.md 를 쓴다                         -> 그것은 /loop-evaluator
X 이전 회차의 evidence/ memory/ 를 덮어쓴다
X 한 번 호출에 여러 회차를 연속으로 돈다        -> 한 회차만
X 실패 원인과 무관한 부분까지 함께 고친다
X 요구되지 않은 기능을 추가해 실패를 우회한다
```

## 8. 불변 조건 (ARCHITECTURE.md 블록 H)

| # | 불변 대상 |
| --- | --- |
| H1 | 게이트 목록·통과 기준·임계값 |
| H2 | 완료 정의 |
| H3 | 이미 저장된 증거·메모리 |
| H4 | `ARCHITECTURE.md` |
| H5 | <주제별 추가 불변 조건> |

건드려야 한다고 판단되면 **수정하지 말고 `ESCALATE`** 한다.
````

## 3. 생성 후 자기 점검 (loop-builder가 수행)

```text
[ ] 프론트매터 name = loop-run, description 한 줄, 트리거 문구·주제 키워드 포함
[ ] 8개 섹션이 모두 있는가
[ ] 1절에 "memory/<S>/INDEX.md 를 먼저 읽는다"가 있는가
[ ] 게이트 표의 모든 행에 실행 명령 또는 관찰 절차가 있는가 (빈칸·추측 금지)
[ ] 게이트 표의 모든 행에 증거 파일과 데이터 타입이 있는가
[ ] manifest.json 스펙이 들어 있는가
[ ] 메모리 6절 양식이 들어 있는가
[ ] 판정 5종과 각각의 다음 행동이 있는가
[ ] 회차 번호 계산법과 반복 상한이 있는가
[ ] "한 번 호출에 한 회차만"이 명시돼 있는가
[ ] 템플릿의 <...> 자리표시자가 남아 있지 않은가
[ ] 이 주제와 무관한 예시 문구가 남아 있지 않은가
```

## 4. 흔한 실패 사례

| 증상 | 원인 | 고치는 법 |
| --- | --- | --- |
| "루프 진행해"라고 했는데 스킬이 안 뜬다 | description에 트리거 문구가 없다 | description에 발화 예시를 넣는다 |
| loop-run이 아키텍처를 고쳐 버린다 | 7절 금지 목록이 빠졌다 | 금지 목록과 불변 조건을 반드시 넣는다 |
| 회차가 끝없이 이어진다 | "한 회차만" 문구와 상한 계산이 없다 | 0절·6절에 명시한다 |
| 증거가 "통과했습니다" 한 줄뿐 | 증거 표에 데이터 타입이 없다 | 파일명·타입·내용을 지정한다 |
| 다음 회차가 같은 실수를 반복한다 | 1절 메모리 로드가 없다 | 1절을 절대 빼지 않는다 |
| 게이트를 통과시키려고 기준을 낮춘다 | 불변 조건이 없다 | 8절 H1~H3을 항상 넣는다 |
