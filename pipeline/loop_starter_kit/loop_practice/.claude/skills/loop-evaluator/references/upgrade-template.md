# `upgrade/<세션>.md` 작성 템플릿

`/loop-evaluator`가 쓰는 **유일한 산출 파일**의 고정 양식이다.

```text
세션당 파일 하나.  절 순서·제목·표 구조를 바꾸지 않는다.
모든 세션의 보고서가 같은 모양이어야 교육생이 "무엇이 나아졌는지"를 나란히 볼 수 있다.
```

가독성 규칙 6가지:

```text
1. 맨 위 3줄 안에 판정과 이유가 보인다
2. 한 절에 한 가지 일만 한다
3. 사실(표)과 설명(문장)을 섞지 않는다 — 표로 먼저, 문장으로 나중
4. 모든 지적 옆에 근거 파일 경로가 있다
5. 모든 문제 아래에 해결책이 있다 (문제만 나열하지 않는다)
6. 한 문단은 4줄을 넘기지 않는다
```

## 2. 문제 블록 작성 예시

주제가 달라도 형식은 같다. 아래는 서로 다른 주제의 예시 셋이다.

### 예시 A — 증거가 없는데 통과로 기록된 경우

```markdown
### 문제 1. "확인했다"는 기록은 있는데 확인한 흔적이 없습니다

| 항목 | 내용 |
| --- | --- |
| 확인 수준 | 증거로 확인 |
| 중요도 | 높음 |
| 근거 파일 | `evidence/S01/run-02/manifest.json` — G3의 `result`는 `PASS`인데 `observed`가 빈 문자열이고, `evidence` 배열이 비어 있음 |
| 8문항 | 4 재루프 조건 |
| 9블록 | D 증거 규약 |

**무슨 일이 있었나**
2회차에서 G3이 PASS로 기록됐습니다. 그런데 관측값이 비어 있고, 해당 게이트의 증거 파일이 폴더에 없습니다.
3회차는 G3을 이미 통과한 것으로 보고 건드리지 않았습니다.

**왜 그렇게 됐나**
게이트 통과를 선언할 때 증거 파일 존재를 확인하는 단계가 없어, 판단만 기록되고 근거는 남지 않았습니다.

**루프 설계의 어느 빈틈 때문인가**
아키텍처 블록 D에 "증거 파일이 없으면 PASS로 기록할 수 없다"는 규칙이 없습니다.
게이트와 증거가 표로 연결돼 있지만, 실행 시 그 연결을 강제하는 문장이 없었습니다.

**해결책**
블록 D에 다음을 추가합니다. "게이트를 PASS로 기록하려면 `manifest.json`의 `observed`가 비어 있지 않아야 하고,
`evidence` 배열의 파일이 실제로 회차 폴더에 존재해야 한다. 둘 중 하나라도 없으면 그 게이트는 `BLOCKED`이다."

**해결됐다고 볼 기준**
다음 세션의 모든 회차에서 `manifest.json`의 PASS 게이트 수와, 실제로 존재하는 증거 파일에 연결된 게이트 수가 같습니다.
```

### 예시 B — 같은 실패를 반복한 경우

```markdown
### 문제 2. 같은 원인으로 세 번 실패했는데 접근이 바뀌지 않았습니다

| 항목 | 내용 |
| --- | --- |
| 확인 수준 | 기록으로 확인 |
| 중요도 | 높음 |
| 근거 파일 | `memory/S01/run-01.md`, `run-02.md`, `run-03.md` — 3절 "직접 원인"이 세 번 모두 같은 문장 |
| 8문항 | 5 루프 간 Memory |
| 9블록 | E 메모리 규약 / F 재시도 규칙 |

**무슨 일이 있었나**
1·2·3회차의 실패 원인이 동일하게 기록돼 있고, 5절 "다음 회차에 반영할 것"도 거의 같은 내용이 반복됩니다.
반복 상한 5회 중 3회를 같은 시도에 썼습니다.

**왜 그렇게 됐나**
메모리에 "무엇을 시도했는가"는 남았지만 "그 접근이 왜 통하지 않았는가"가 남지 않아,
다음 회차가 같은 접근을 조금 바꿔 다시 시도했습니다.

**루프 설계의 어느 빈틈 때문인가**
블록 F에 "같은 원인으로 2회 연속 실패하면 접근을 바꾸고, 3회째에는 ESCALATE한다"는 분기 규칙이 없습니다.
`INDEX.md`의 "반복된 실패" 표도 갱신되지 않았습니다.

**해결책**
블록 F에 다음을 추가합니다. "같은 게이트가 같은 직접 원인으로 2회 연속 실패하면 다음 회차는 다른 접근을 쓴다.
3회째 같은 실패면 `ESCALATE`로 종료하고 선택지를 사용자에게 넘긴다."
블록 E에는 "회차 종료 시 `INDEX.md`의 반복된 실패 표를 반드시 갱신한다"를 추가합니다.

**해결됐다고 볼 기준**
다음 세션에서 같은 직접 원인이 3회 이상 나타나지 않거나, 3회째에 `ESCALATE`로 종료됩니다.
```

### 예시 C — 완료 정의를 다 못 채웠는데 성공처럼 끝난 경우

```markdown
### 문제 3. 상한에 걸려 끝났는데 보고만 보면 완료된 것처럼 읽힙니다

| 항목 | 내용 |
| --- | --- |
| 확인 수준 | 증거로 확인 |
| 중요도 | 보통 |
| 근거 파일 | `evidence/S01/run-05/manifest.json` — `verdict: "EXHAUSTED"`, `unmet: ["D3","D4"]` |
| 8문항 | 6 반복 상한 / 8 종료 및 인간 이관 |
| 9블록 | G 종료 조건 |

**무슨 일이 있었나**
5회차에서 상한에 도달해 `EXHAUSTED`로 끝났고 완료 정의 D3·D4가 미충족 상태입니다.
그런데 `memory/S01/INDEX.md`의 현재 상태 칸은 "진행 중"으로 남아 있어, 무엇이 남았는지 한눈에 보이지 않습니다.

**왜 그렇게 됐나**
종료 시 `INDEX.md` 헤더를 갱신하라는 지시가 실행 절차에 없었습니다.

**루프 설계의 어느 빈틈 때문인가**
블록 G가 판정 조건만 정하고, 판정 결과를 어디에 어떻게 남기는지는 정하지 않았습니다.

**해결책**
블록 G에 다음을 추가합니다. "세션이 `SUCCESS`가 아닌 상태로 끝나면 `INDEX.md` 헤더의 현재 상태를 그 상태로 바꾸고,
미충족 완료 정의 ID를 '아직 해결되지 않은 항목' 표 맨 위에 옮긴다."

**해결됐다고 볼 기준**
다음 세션 종료 시 `INDEX.md` 헤더 상태와 마지막 `manifest.json`의 `verdict`가 일치합니다.
```

| "커버리지가 부족합니다" | 숫자만 있고 결과가 없다 | "D3은 어떤 게이트도 검사하지 않아, 깨져도 SUCCESS가 나옵니다" |

## 4. 실제 실패 사례 목록 (주제 무관 · 루프 설계 쪽)

**전수 검사하지 않는다.** 이번 세션 자료에서 실제로 확인된 것만 고른다.

| 사례 | 무슨 일이 벌어지는가 | 관련 블록 |
| --- | --- | --- |
| 증거 없는 PASS | `manifest.json`은 PASS인데 `observed`가 비었거나 증거 파일이 없다 | D |
| 게이트가 완료 정의를 덜 덮음 | D1~D5 중 두 개는 어떤 게이트와도 연결되지 않아, 깨져도 SUCCESS가 난다 | A·C |
| 기준이 감각 표현 | "자연스러우면 통과" 같은 기준이라 회차마다 판정이 흔들린다 | C |
| 실행 명령이 추측 | 아키텍처의 명령과 `manifest.json`의 `command`가 다르다 | C |
| 요약본만 증거 | 원본 로그를 지우고 3줄 요약만 남아 재검증이 불가능하다 | D |
| 기계 판독 증거 부재 | `.png`만 있고 수치를 대조할 `.json`/`.csv`가 없다 | D |
| 실패 원인이 추상적 | 3절 직접 원인이 "실패"로만 적혀 다음 회차가 같은 시도를 반복한다 | E |
| 메모리 미반영 | 5절 "다음 회차에 반영할 것"이 다음 회차 1절에 나타나지 않는다 | E |
| 해결/미해결 미구분 | 이미 해결된 항목이 미해결 표에 계속 남아 우선순위가 흐려진다 | E |
| 고칠 수 없는 실패에 RETRY | 도구가 없어 확인 자체가 불가한데 계속 재시도해 상한만 소진한다 | F |
| 반복 실패에 분기 없음 | 같은 원인 3회 실패인데 접근도 판정도 그대로다 | F |
| 상한이 안 걸림 | 상한 5회인데 7회차 기록이 있다 | G |
| 상한 소진이 성공처럼 보임 | `EXHAUSTED`인데 요약 문장만 읽으면 완료로 읽힌다 | G |
| 기준이 완화됨 | 회차 4절 "바꾼 것"에 게이트 정의나 임계값이 들어 있다 | H |
| 증거 덮어쓰기 | 같은 회차 폴더가 재사용돼 이전 관측값이 사라졌다 | H |
| 한 호출에 여러 회차 | `run-02.md`와 `run-03.md`의 일시가 같고 보고가 한 번뿐이다 | I |
| 아키텍처 자가 수정 | 4절 변경 파일에 `ARCHITECTURE.md`가 들어 있다 | H·I |
| 이관 정보 부족 | `ESCALATE`인데 원인과 선택지 없이 "문제가 있습니다"만 있다 | F·I |
| 1회 범위 과다 | 모든 회차가 미완으로 끝나고 매번 같은 STEP에서 시간이 끊긴다 | B |
