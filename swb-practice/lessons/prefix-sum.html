언제 쓰나

  • 배열은 바뀌지 않고, "l번부터 r번까지의 합"을 여러 번 묻는다 → 누적합
  • "l번부터 r번까지 전부 v를 더한다"를 잔뜩 한 뒤 마지막에 한 번 결과를 본다 → 차분 배열
  • "합이 K 이하인 가장 긴 구간", "조건을 만족하는 연속 구간의 개수" → 투 포인터

셋 다 "구간을 매번 처음부터 다시 세지 않는다"는 같은 생각이다. 값이 계속 바뀌면서 질의도 섞이면 이것만으로는 안 되고 펜윅 트리, 세그먼트 트리, 버킷으로 넘어간다.

누적합

S[i] = 앞에서부터 i개를 더한 값으로 정의한다. 길이가 N+1이고 S[0] = 0이다. 그러면 구간 [l, r]의 합은 뺄셈 한 번이다.

a      =    3   1   4   1   5
S      = 0  3   4   8   9  14
            ↑ S[1]         ↑ S[5]

sum(a[1..3]) = 1+4+1 = S[4] - S[1] = 9 - 3 = 6
from itertools import accumulate

a = [3, 1, 4, 1, 5]
S = [0] + list(accumulate(a))        # [0, 3, 4, 8, 9, 14]

def range_sum(l, r):                 # 닫힌 구간 [l, r], 0부터 시작
    return S[r + 1] - S[l]

만드는 데 O(N), 질의는 O(1)이다. S의 인덱스가 하나 밀려 있다는 것만 기억하면 된다.

2차원 누적합

격자에서 직사각형 합을 물을 때 쓴다. S[i][j] = (0,0)부터 (i-1, j-1)까지 직사각형의 합.

def build2d(g, R, C):
    S = [[0] * (C + 1) for _ in range(R + 1)]
    for i in range(R):
        row = 0
        for j in range(C):
            row += g[i][j]
            S[i + 1][j + 1] = S[i][j + 1] + row
    return S

def rect(S, r1, c1, r2, c2):         # (r1,c1) ~ (r2,c2) 양 끝 포함
    return S[r2 + 1][c2 + 1] - S[r1][c2 + 1] - S[r2 + 1][c1] + S[r1][c1]

빼기 두 번을 하면 왼쪽 위 모서리가 두 번 빠지므로 한 번 다시 더한다(포함-배제).

차분 배열

누적합의 반대 방향이다. 구간 [l, r]에 v를 더하라는 명령을 받으면, D[l] += v, D[r+1] -= v만 한다. 명령을 모두 받은 뒤 D의 누적합을 구하면 각 칸에 더해진 양이 나온다.

길이 6, [1,3]에 +2, [2,5]에 +1

D      =  0  +2  +1   0  -2   0  (-1은 범위 밖)
누적   =  0   2   3   3   1   1
D = [0] * (N + 1)
for l, r, v in commands:
    D[l] += v
    D[r + 1] -= v                    # 길이를 N+1로 잡아 r = N-1일 때도 안전
add = list(accumulate(D))[:N]

B형에서는 "명령 도중에 질의가 섞이는" 경우가 많아서 차분 배열만으로는 부족한 때가 많다. 그래도 펜윅 트리로 구간 더하기 + 한 점 조회를 할 때 바로 이 생각을 쓴다(차분 배열을 펜윅 트리에 담는다).

투 포인터 (슬라이딩 윈도우)

값이 모두 0 이상일 때, 구간을 오른쪽으로 늘리면 합이 커지고 왼쪽을 줄이면 합이 작아진다. 이 단조성 덕분에 왼쪽 끝 lo와 오른쪽 끝 hi를 둘 다 앞으로만 움직여서 O(N)에 모든 후보를 본다.

def longest_at_most(a, K):           # 합이 K 이하인 가장 긴 연속 구간의 길이
    best = lo = cur = 0
    for hi in range(len(a)):
        cur += a[hi]                 # 오른쪽으로 한 칸 늘리고
        while cur > K:               # 조건이 깨지면 왼쪽을 줄인다
            cur -= a[lo]
            lo += 1
        best = max(best, hi - lo + 1)
    return best

while문이 안에 있어도 lo는 전체에서 최대 N번만 움직이므로 전체 O(N)이다. 음수가 섞이면 단조성이 깨지므로 투 포인터를 쓸 수 없다(누적합 + 정렬/해시로 바꾼다).

합이 정확히 K인 구간의 개수 (음수 포함 가능)

누적합과 dict를 같이 쓰는 유명한 형태다. 구간 [l, r]의 합이 K ⇔ S[r+1] - S[l] = K ⇔ S[l] = S[r+1] - K. 앞에서 나온 누적합의 개수를 세어 두면 된다.

def count_sum_k(a, K):
    seen = {0: 1}                    # S[0] = 0
    cur = ans = 0
    for x in a:
        cur += x
        ans += seen.get(cur - K, 0)
        seen[cur] = seen.get(cur, 0) + 1
    return ans

B형에서 보이는 모양

  • init에서 고정 배열을 받고, 질의만 수만 번 → init에서 누적합을 한 번 만든다.
  • 시간 축 위의 예약·대여: "t1부터 t2까지 사용 중" → 시간 차분 배열로 겹치는 수를 센다.
  • 고정된 지도에서 "이 직사각형 안 장애물 개수" → 2차원 누적합.
  • 값이 바뀐다면? 한 칸 수정이 드물면(수백 번) 수정할 때마다 누적합을 다시 만들어도 되지만, 자주 바뀌면 펜윅 트리로 바꾼다.

자주 하는 실수

  • 한 칸 밀림: S[r] - S[l]은 [l, r-1]의 합이다. 닫힌 구간이면 S[r+1] - S[l].
  • 차분 배열 길이: D[r+1]이 범위를 벗어나지 않도록 길이를 N+1로 잡는다.
  • 투 포인터에 음수: 값에 음수가 있으면 "줄이면 작아진다"가 성립하지 않는다.
  • 값이 바뀌는데 누적합: 한 칸이 바뀌면 그 뒤의 S가 전부 바뀐다(O(N)). 수정이 잦으면 펜윅 트리.
