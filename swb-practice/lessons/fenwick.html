언제 쓰나

  • 한 칸의 값이 계속 바뀌고, 그 사이사이에 "l번부터 r번까지의 합"을 묻는다.
  • "앞에서부터 세어서 k번째"를 묻는다 (k번째 책, k번째로 작은 점수, k번째 빈자리).
  • "x보다 작은 값이 몇 개인가"를 값이 들어오고 나갈 때마다 묻는다 (값을 인덱스로 쓰는 개수 배열).

합만 필요하다면 세그먼트 트리보다 코드가 훨씬 짧고(10줄 남짓) 파이썬에서도 빠르다. 최댓값·최솟값은 펜윅 트리로 다루기 어렵다. 그때는 세그먼트 트리를 쓴다.

왜 누적합으로는 안 되나

누적합은 질의가 O(1)이지만, 한 칸을 바꾸면 그 뒤의 누적합이 전부 바뀐다(O(N)). 반대로 배열을 그대로 두면 수정은 O(1)이지만 질의가 O(N)이다. 펜윅 트리는 둘 다 O(log N)으로 맞춘다.

핵심 아이디어: 칸마다 맡은 구간의 길이가 다르다

배열을 1번부터 쓴다. tree[i]는 i로 끝나는 길이 i & -i짜리 구간의 합을 저장한다. i & -i는 i를 2진수로 썼을 때 가장 낮은 1비트의 값이다.

i       2진수   i & -i   tree[i]가 맡는 구간
1       0001     1       [1, 1]
2       0010     2       [1, 2]
3       0011     1       [3, 3]
4       0100     4       [1, 4]
5       0101     1       [5, 5]
6       0110     2       [5, 6]
7       0111     1       [7, 7]
8       1000     8       [1, 8]

앞에서 7개의 합 = tree[7] + tree[6] + tree[4]
                  [7,7]    [5,6]    [1,4]      7 → 6 → 4 → 0  (i -= i & -i)

a[5]가 바뀌면 고칠 칸 = tree[5], tree[6], tree[8]
                                         5 → 6 → 8 → 16  (i += i & -i)

합을 구할 때는 가장 낮은 1비트를 빼면서 내려가고, 값을 고칠 때는 가장 낮은 1비트를 더하면서 올라간다. 어느 쪽이든 1비트가 하나씩 줄거나 자리가 올라가므로 최대 log N번이다.

코드

N = 0
tree = []

def init(n):
    global N, tree
    N = n
    tree = [0] * (N + 1)        # 1번부터 N번까지 사용

def add(i, v):                  # a[i] += v      (i는 1부터)
    while i <= N:
        tree[i] += v
        i += i & -i

def prefix(i):                  # a[1] + ... + a[i]
    s = 0
    while i > 0:
        s += tree[i]
        i -= i & -i
    return s

def range_sum(l, r):            # a[l] + ... + a[r]
    return prefix(r) - prefix(l - 1)

문제의 칸 번호가 0부터라면 함수에 넘길 때 +1한다. 이 변환을 한 곳(함수 입구)에서만 하면 실수가 줄어든다.

"바꾼다"는 "차이만큼 더한다"

펜윅 트리는 더하기만 안다. a[i]를 x로 바꾸라는 명령이면 원래 배열 a를 따로 들고 있다가 add(i, x - a[i]), a[i] = x로 처리한다.

처음 배열이 주어질 때 O(N)에 만들기

def build(a):                   # a는 0부터 시작하는 길이 N 리스트
    global tree
    tree = [0] + list(a)
    for i in range(1, N + 1):
        j = i + (i & -i)
        if j <= N:
            tree[j] += tree[i]  # 자기 구간 합을 바로 위 부모에게 넘긴다

add를 N번 부르면 O(N log N)이다. N = 10만이면 둘 다 괜찮지만, 테스트 케이스가 많으면 이 방법이 확실히 빠르다.

k번째 찾기 (이분 탐색 없이 O(log N))

값이 모두 0 이상일 때, "prefix(i) ≥ k가 되는 가장 작은 i"를 찾는다. prefix를 이분 탐색하면 O(log² N)이지만, 트리 구조를 따라 큰 단계부터 내려가면 O(log N)이다.

LOG = 1
# init에서: while (1 << LOG) <= N: LOG += 1

def kth(k):                     # prefix(i) >= k인 가장 작은 i. 전체 합 < k이면 N+1
    pos = 0
    step = 1 << LOG
    while step:
        nxt = pos + step
        if nxt <= N and tree[nxt] < k:
            pos = nxt           # [pos+1, nxt] 구간을 통째로 건너뛴다
            k -= tree[nxt]
        step >>= 1
    return pos + 1
a = [1번..8번] = 2 0 3 1 0 4 0 2   (책 권수), k = 6번째 책

(LOG=4라서 step 16부터 시작하지만 16 > N이라 넘어간다)
step 8: tree[8]=12 ≥ 6 → 건너뛰지 않음
step 4: tree[4]=6  ≥ 6 → 건너뛰지 않음
step 2: tree[2]=2  < 6 → pos=2, k=4
step 1: tree[3]=3  < 4 → pos=3, k=1
답 = pos + 1 = 4번 칸   (1~3번에 5권, 4번 칸에 6번째 책)

핵심은 tree[pos + step]이 정확히 [pos+1, pos+step] 구간의 합이라는 점이다. pos는 항상 step보다 큰 2의 거듭제곱들의 합이라서 이 성질이 지켜진다.

응용: 구간 더하기 + 한 점 조회

차분 배열을 펜윅 트리에 담는다. [l, r]에 v를 더하면 add(l, v), add(r + 1, -v). i번 칸의 현재 값은 prefix(i)이다.

def range_add(l, r, v):
    add(l, v)
    if r + 1 <= N:
        add(r + 1, -v)

def point(i):
    return prefix(i)            # 원래 값이 있다면 base[i] + prefix(i)

구간 더하기와 구간 합을 둘 다 해야 하면 펜윅 트리 두 개를 쓰는 방법이 있지만, 시험에서는 버킷이나 lazy 세그먼트 트리가 더 떠올리기 쉽다.

응용: 값의 개수 세기

점수가 0~100,000 범위의 정수라면, "점수 s인 사람 수"를 펜윅 트리에 담는다. 등록은 add(s+1, 1), 탈퇴는 add(s+1, -1). 그러면

  • "점수가 s 미만인 사람 수" = prefix(s)
  • "k번째로 작은 점수" = kth(k) - 1

정렬된 리스트에 insort로 넣으면 넣을 때마다 O(N)이라 느려지지만, 펜윅 트리는 넣고 빼고 순위를 묻는 것이 모두 O(log V)이다. 값의 범위가 너무 크면(10억) 등장할 값만 모아 정렬한 뒤 순서 번호로 바꾼다(좌표 압축).

자주 하는 실수

  • 0번 인덱스: i = 0으로 add를 부르면 i & -i가 0이라 무한 루프에 빠진다. 반드시 1부터 쓴다.
  • 바꾸기를 더하기로: add(i, x)는 x를 더한다. 값을 x로 바꾸려면 차이를 더한다.
  • kth의 LOG: 1 << LOG가 N 이상이 되도록 잡아야 큰 구간을 놓치지 않는다.
  • 음수가 섞인 kth: 값이 음수가 될 수 있으면 누적합이 단조롭지 않아 kth가 틀린다. 개수(0 이상)에만 쓴다.
  • init에서 트리를 새로 만들지 않음: 테스트 케이스마다 tree = [0] * (N + 1)을 다시 만든다.
