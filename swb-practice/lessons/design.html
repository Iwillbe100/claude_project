앞의 강의들은 알고리즘을 하나씩 다뤘다. 실제 B형 문제는 보통 자료구조 두세 개를 묶어서 써야 하고, 4시간 안에 짜고 스스로 검증까지 해야 한다. 이 강의는 그 과정을 순서대로 정리한다.

1단계: 함수별 요구 사항 표 만들기 (코드 쓰기 전 10~20분)

문제를 읽고 바로 코드를 쓰지 않는다. 함수마다 아래 표를 종이에 채운다.

함수호출 수무엇을 찾나 / 바꾸나허용 복잡도쓸 자료구조
add(id, score)3만id 등록, 점수 저장O(log N)dict + 힙
update(id, score)3만점수 변경O(log N)dict 갱신 + 힙에 새로 push (지연 삭제)
top(k)1천점수 높은 순 k개 (k ≤ 10)O(k log N)힙에서 k개 꺼내고 다시 넣기

호출 수 × 함수 하나의 일 = 전체 일의 양이다. 파이썬에서 전체가 수천만 이하면 안전하다(B형 가이드의 표). 이 표가 채워지면 설계는 끝난 것이고, 코드는 그대로 옮겨 쓰면 된다.

2단계: 자주 쓰는 조합 패턴

ID 압축: 큰 ID를 0, 1, 2, ...로

ID가 10억까지 가거나 문자열이면, 처음 볼 때 순서 번호를 붙여 리스트 인덱스로 쓴다. dict 조회는 한 번만 하고, 나머지는 빠른 리스트 연산이 된다.

idx = {}                         # 원래 ID → 0부터 시작하는 번호
score = []                       # 번호로 접근하는 정보들
alive = []

def get_idx(uid):
    i = idx.get(uid)
    if i is None:
        i = idx[uid] = len(score)
        score.append(0)
        alive.append(True)
    return i

지연 삭제 + 버전 스탬프

힙 안의 값은 바꿀 수 없으므로, 바뀔 때마다 새 항목을 넣고 꺼낼 때 최신인지 확인한다(힙 강의). 확인 방법은 둘 중 하나다.

# 방법 1: 현재 값과 비교 (값이 같은 상태로 다시 돌아오는 일이 없을 때)
while heap and score[heap[0][1]] != -heap[0][0]:
    heappop(heap)

# 방법 2: 버전 번호 (가장 안전하다)
ver[i] += 1
heappush(heap, (-new_score, i, ver[i]))
...
while heap and (not alive[heap[0][1]] or heap[0][2] != ver[heap[0][1]]):
    heappop(heap)

방법 1은 "점수가 50 → 70 → 50"처럼 옛 값으로 돌아오면 옛 항목이 살아 있는 것처럼 보이는 함정이 있다(중복 출력). 헷갈리면 버전 번호를 쓴다.

상위 k개를 꺼내고 되돌리기

def top(k):
    res, back = [], []
    while heap and len(res) < k:
        item = heappop(heap)
        if is_valid(item):
            res.append(item[1])
            back.append(item)    # 유효한 것만 다시 넣는다 (무효는 버려서 힙을 청소)
    for item in back:
        heappush(heap, item)
    return res

그룹별 힙 / 그룹별 버킷

"카테고리별 최고 점수", "부서별 가장 오래된 요청"처럼 그룹마다 질의가 따로라면 heaps = defaultdict(list)처럼 그룹마다 자료구조를 하나씩 둔다. 한 항목이 그룹을 옮기면 옛 그룹에서는 지연 삭제, 새 그룹에는 push.

정렬 기준은 튜플로

"점수 높은 순, 같으면 시간 이른 순, 같으면 ID 작은 순"은 (-score, time, id) 튜플 하나다. 힙, sorted(key=...), min() 모두 같은 튜플로 비교한다. 동점 규칙을 if문으로 짜면 반드시 빠뜨리는 경우가 생긴다.

3단계: 함수 하나씩 짜고 바로 확인

  1. init과 가장 단순한 함수(등록)를 먼저 짠다.
  2. 문제의 예시를 직접 입력으로 넣어 본다. 이 사이트의 "직접 입력" 체크박스가 그 용도다.
  3. 함수를 하나 추가할 때마다 샘플을 다시 돌린다. 세 함수를 한꺼번에 짠 뒤 틀리면 어디서 틀렸는지 찾기 어렵다.

4단계: 브루트포스와 무작위 대조 (스트레스 테스트)

샘플은 맞는데 제출하면 틀릴 때 쓰는 가장 강력한 방법이다. 느리지만 확실히 맞는 코드(브루트포스)를 따로 짜고, 작은 무작위 입력으로 둘을 비교한다. 시험장에서도 20분이면 짤 수 있고, 반례를 거의 항상 찾아 준다.

# stress.py — solution.py와 같은 폴더에 두고 실행한다
import random
import solution as fast

class Brute:                     # 리스트 하나로 문제를 그대로 흉내 낸다
    def init(self, N):
        self.a = [0] * N
    def add(self, i, v):
        self.a[i] += v
    def query(self, l, r):
        return sum(self.a[l:r + 1])

for trial in range(10000):
    rng = random.Random(trial)
    N = rng.randint(1, 8)        # 아주 작게: 반례가 나와도 손으로 따라갈 수 있게
    slow = Brute()
    fast.init(N); slow.init(N)
    log = [f"init({N})"]
    for _ in range(rng.randint(1, 10)):
        if rng.random() < 0.5:
            i, v = rng.randrange(N), rng.randint(-3, 3)
            fast.add(i, v); slow.add(i, v)
            log.append(f"add({i}, {v})")
        else:
            l = rng.randrange(N); r = rng.randrange(l, N)
            a, b = fast.query(l, r), slow.query(l, r)
            log.append(f"query({l}, {r}) -> {a} (정답 {b})")
            if a != b:
                print("반례 발견 (seed", trial, ")")
                print("\n".join(log))
                raise SystemExit
print("10000번 모두 일치")
  • N과 호출 수를 아주 작게 잡는다. 작은 반례가 디버깅하기 쉽다. 대부분의 버그는 N ≤ 5에서 이미 드러난다.
  • 값의 범위도 작게(0~3) 잡아야 동점이 자주 생겨 동점 처리 버그가 잡힌다.
  • seed를 출력해 두면 같은 반례를 다시 만들 수 있다.

5단계: 시간 초과가 날 때

  1. 어느 함수가 느린지 먼저 찾는다. 함수마다 호출 수 × 한 번의 일을 다시 계산한다. 숨은 O(N): x in list, list.remove, list.index, list.pop(0), list.insert(0, x), 슬라이싱 a[l:r], sum(), min(), sorted()를 매 호출마다 쓰고 있지 않은지 본다.
  2. 설계가 맞는데 상수가 크다면:
    • 반복문 안에서 쓰는 전역 리스트·함수는 지역 변수로 받아 두기 (t = tree)
    • 작은 함수 호출을 반복문 안에 풀어 쓰기 (파이썬은 함수 호출이 비싸다)
    • 클래스 객체 대신 리스트 여러 개(x[i], y[i]) 쓰기
    • dict 키로 튜플 대신 정수 하나 쓰기 (cx * 100000 + cy)
  3. 그래도 느리면 자료구조를 바꾼다(예: 정렬 리스트 → 힙, 구간 루프 → 버킷).
