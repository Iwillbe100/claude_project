언제 쓰나

  • 지도 위에 물체(택시, 손님, 기지국, 몬스터)가 많고, "이 점에서 거리 L 이내에 있는 것"을 계속 묻는다.
  • 물체가 추가되고, 움직이고, 사라진다.
  • 지도는 매우 넓지만(10억 × 10억일 수도 있다) 물체는 수만 개뿐이다.

B형에서 아주 자주 나오는 유형이다. 매번 모든 물체와 거리를 재면 물체 2만 개 × 호출 3만 번 = 6억 번이라 시간 초과가 난다.

핵심 아이디어: 지도를 L×L 칸으로 자른다

버킷을 2차원으로 한 것이다. 좌표 (x, y)는 칸 (x // L, y // L)에 들어간다. 칸 한 변이 L이면, 거리 L 이내의 점은 자기 칸과 둘레 8칸, 모두 9칸 안에만 있다.

       cx-1    cx     cx+1
     ┌───────┬───────┬───────┐
cy-1 │       │   ·   │       │
     ├───────┼───────┼───────┤
cy   │   ·   │   ★   │       │      ★ = 질의 지점 (x, y)
     ├───────┼───────┼───────┤      · = 거리 L 안에 있을 수 있는 물체
cy+1 │       │     · │       │
     └───────┴───────┴───────┘
  칸 한 변 = L  →  |dx| ≤ L 이면 칸 번호 차이는 최대 1

물체가 고르게 퍼져 있으면 칸 하나에는 평균 몇 개만 들어 있으므로, 질의 한 번이 9칸 × 몇 개 = 수십 번의 일로 끝난다.

자료구조

  • pos[id] = (x, y) : 물체의 현재 위치 (dict)
  • cell[(cx, cy)] = set(id, ...) : 칸마다 들어 있는 물체 (dict of set)

지도가 넓어도 물체가 있는 칸만 dict에 생기므로 메모리는 물체 수에 비례한다. 지도가 작으면(예: 1000 × 1000에 L = 10) 2차원 리스트 [[set() ...]]로 만들어도 된다.

칸 안에 set을 쓰는 이유는 뺄 때 O(1)이기 때문이다. list의 remove는 O(칸 크기)이다.

코드

L = 1
pos = {}
cell = {}

def init(N, mL):
    global L, pos, cell
    L = mL
    pos = {}
    cell = {}

def put(i, x, y):
    pos[i] = (x, y)
    key = (x // L, y // L)
    s = cell.get(key)
    if s is None:
        s = cell[key] = set()
    s.add(i)

def take(i):
    x, y = pos.pop(i)
    cell[(x // L, y // L)].discard(i)

def move(i, x, y):
    take(i)
    put(i, x, y)

def nearest(x, y):
    """거리 L 이내에서 가장 가까운 물체. 동점이면 id가 작은 것. 없으면 -1."""
    cx, cy = x // L, y // L
    best = None                         # (거리, id)
    for gx in range(cx - 1, cx + 2):
        for gy in range(cy - 1, cy + 2):
            s = cell.get((gx, gy))
            if not s:
                continue
            for i in s:
                px, py = pos[i]
                d = abs(px - x) + abs(py - y)
                if d <= L and (best is None or (d, i) < best):
                    best = (d, i)
    return best[1] if best else -1

동점 처리를 튜플 비교 (d, i) < best로 한 줄에 끝낸 것을 보자. "거리가 짧은 것, 같으면 id가 작은 것" 같은 규칙은 튜플 순서로 그대로 옮긴다.

칸 크기는 어떻게 고르나

칸 크기질의에서 보는 칸특징
L (거리 제한과 같게)3 × 3 = 9칸가장 흔한 선택. 이것부터 생각한다
L보다 작게 (L/2 등)5 × 5 = 25칸칸이 작아 칸마다 물체가 적다. 물체가 한곳에 몰리는 입력에 유리
L보다 크게3 × 3칸에 쓸데없는 물체가 많아진다

칸 크기를 c로 하면 거리 L 이내를 덮으려면 칸 번호 차이가 L // c + 1까지 필요하다. 거리 제한이 없는 "가장 가까운 것"이라면 9칸에서 없을 때 반지름을 1칸씩 넓혀 가며 찾는다. 이때 이미 찾은 후보가 있어도 한 바퀴 더 봐야 할 수 있다(칸 경계 근처의 더 가까운 점).

맨해튼 거리 vs 유클리드 거리

  • 맨해튼: |dx| + |dy|. 격자 이동 문제에서 쓴다.
  • 유클리드: 제곱근을 쓰지 말고 제곱끼리 비교한다. dx*dx + dy*dy <= L*L. 실수 오차가 없다.
  • 체비셰프: max(|dx|, |dy|). "정사각형 범위 안"이라는 말이면 이것이다.

세 가지 모두 거리 L 이내라면 |dx| ≤ L, |dy| ≤ L이라서 9칸 방법이 그대로 통한다.

변형: 직사각형 영역 질의

"(x1, y1) ~ (x2, y2) 안의 물체 개수"라면 x1 // L부터 x2 // L까지의 칸을 모두 본다. 칸이 영역 안에 통째로 들어가면 len(set)만 더하고, 걸치는 가장자리 칸만 하나씩 확인한다. 1차원 버킷의 "통째로 덮는 버킷 / 걸치는 양 끝" 처리와 같다.

자주 하는 실수

  • 이동할 때 옛 칸에서 빼지 않음: 위치만 바꾸고 칸 set을 그대로 두면, 옛 칸에서 유령처럼 다시 발견된다. 이동 = 빼기 + 넣기.
  • 음수 좌표: 파이썬의 //는 내림이라 -1 // 10 = -1이다. 그래서 음수 좌표도 그대로 된다. (C++의 나눗셈과 다르다.)
  • 거리 확인 생략: 9칸 안에 있다고 거리 L 이내인 것은 아니다. 반드시 실제 거리를 다시 잰다.
  • 칸 순회 중 set 변경: for i in s 안에서 s에 넣거나 빼면 오류가 난다. 후보를 먼저 고르고, 반복이 끝난 뒤 지운다.
  • 동점 규칙: set은 순서가 없다. "먼저 찾은 것"에 기대지 말고 규칙대로 직접 비교한다.

복잡도

넣기, 빼기, 이동은 O(1)이다. 질의는 O(9칸에 있는 물체 수)이다. 물체가 한 칸에 몰리는 최악의 입력에서는 느려질 수 있으므로, 문제의 제약(같은 칸에 최대 몇 개, 좌표 분포)을 확인한다.
