언제 쓰나

  • 정렬된 데이터에서 값이나 위치를 찾을 때
  • "조건을 만족하는 최소(또는 최대) 값"을 구하는데 후보가 아주 많을 때 (예: 10억)

두 가지 종류

1. 정렬된 배열에서 찾기

파이썬은 bisect가 이미 있다.

from bisect import bisect_left, bisect_right

a = [1, 3, 3, 7, 9]
bisect_left(a, 3)                       # 1 → 3 이상이 처음 나오는 위치
bisect_right(a, 3)                      # 3 → 3 초과가 처음 나오는 위치
bisect_right(a, 3) - bisect_left(a, 3)  # 2 → 3의 개수
bisect_right(a, 8)                      # 4 → 8 이하인 값의 개수

2. 답에 대해 이분 탐색 (파라메트릭 서치)

"최소 시간이 얼마인가?"를 바로 구하기는 어렵지만, "시간 T가 주어지면 가능한가?"는 쉽게 확인할 수 있다면, T를 이분 탐색한다.

단조성이 핵심

이분 탐색이 되려면 "가능 / 불가능"이 한 번만 바뀌어야 한다.

T :   1   2   3  ...  27  28  29  30 ...
가능:  X   X   X  ...   X   O   O   O ...
                            ↑ 우리가 찾는 답 (가능한 최소 T)

입국 심사에서 시간 T 동안 처리할 수 있는 사람 수는 sum(T // t)이고 T가 커질수록 줄어들지 않는다. 그래서 단조성이 성립한다.

"가능한 최솟값" 템플릿

def min_time(M):
    lo, hi = 1, min(desks) * M          # 답이 반드시 이 범위 안에 있다
    while lo < hi:
        mid = (lo + hi) // 2
        if sum(mid // t for t in desks) >= M:   # mid 시간이면 M명을 처리할 수 있다
            hi = mid                    # 가능 → 더 작은 값도 가능한지 본다 (mid도 후보)
        else:
            lo = mid + 1                # 불가능 → mid는 답이 아니다
    return lo

"가능한 최댓값" 템플릿

예: 랜선을 같은 길이로 잘라 K개 이상 만들 수 있는 최대 길이.

lo, hi = 1, max(cables)
while lo < hi:
    mid = (lo + hi + 1) // 2            # 올림! 안 그러면 무한 루프
    if sum(c // mid for c in cables) >= K:
        lo = mid                        # 가능 → 더 큰 값을 본다
    else:
        hi = mid - 1
print(lo)

어디서 틀리나

  • 범위 끝(hi)이 너무 작다. 답이 범위 밖에 있으면 엉뚱한 값이 나온다. 확실히 가능한 값으로 잡는다. (입국 심사: 가장 빠른 심사대 혼자서 M명을 처리하는 시간)
  • 최댓값 템플릿에서 (lo + hi) // 2를 쓰면 lo = mid일 때 변하지 않아 무한 루프에 빠진다. 올림을 쓴다.
  • 가능 여부 확인이 느리다. 확인에 O(N)이 들면 전체는 O(N log(범위))이다. 호출 횟수까지 곱해서 계산한다.

복잡도

범위가 1018이어도 반복은 약 60번이다. 여기에 확인 비용을 곱하면 된다.
