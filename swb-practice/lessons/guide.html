B형은 어떤 시험인가

B형은 함수 구현형이다. 입력을 읽고 출력하는 코드는 이미 주어져 있고(이 사이트에서는 main.py), 우리는 init, add, query 같은 함수 몇 개의 내부만 채운다. 채점 프로그램이 함수를 수만 번 호출하면서 반환값을 정답과 비교한다.

  • 테스트 케이스가 여러 개라서 한 프로세스 안에서 init이 여러 번 호출된다. 전역 변수를 init에서 전부 새로 만들지 않으면 앞 케이스의 값이 남아서 틀린다.
  • 케이스 하나라도 반환값이 틀리면 그 케이스는 0점이다. "거의 맞음"은 없다.
  • 전체 시간 제한이 있다. 호출 횟수가 많으므로 함수 하나는 빨라야 한다.

문제를 읽는 순서

  1. 제약 사항부터 본다. 호출 횟수와 값의 크기가 알고리즘을 정해 준다.
  2. 함수마다 무엇을 반환하는지 밑줄 치며 읽는다. 없는 경우(-1), 같은 값이 여러 개일 때의 순서(동점 처리)를 놓치기 쉽다.
  3. 예시를 손으로 따라가 본다.
  4. 자료구조를 고르고, 각 함수가 그 자료구조에서 어떤 연산이 되는지 적는다.

제약으로 알고리즘 고르기

파이썬은 단순 연산이 1초에 대략 1천만~3천만 번이다. 호출 하나에 드는 일의 양에 호출 횟수를 곱해서 그 안에 들어오는지 본다.

호출 횟수함수 하나가 허용하는 일예
~ 1,000O(N) ~ O(N²)매번 전체를 훑어도 된다
~ 30,000O(√N), O(log N), 작은 상수 O(N)접두사 10개 갱신, 깊이 100짜리 조상 탐색
~ 100,000O(log N) 또는 O(1)힙, 이분 탐색, 세그먼트 트리, 유니온 파인드

값의 크기도 본다. 값이 10억이면 "1씩 늘려 가며 확인"은 불가능하고, 이분 탐색이나 수식이 필요하다.

시험장에서 자주 하는 실수

  • init에서 초기화 누락. 전역 리스트·dict를 init에서 비우지 않거나, 함수 안에서 global 선언 없이 대입해서 지역 변수만 바뀐다.
  • 인덱스 기준. 사용자 번호가 1부터인지 0부터인지, 구간이 닫힌 구간 [l, r]인지 확인한다.
  • 없는 경우 반환값. -1, 0 같은 약속을 지키지 않아서 틀린다.
  • 디버그 출력. 실제 시험에서는 제출 전에 print를 모두 지운다. 출력이 채점 출력과 섞일 수 있다.
  • 한 번에 다 짜려는 것. 함수 하나씩 짜고 샘플로 확인하는 편이 빠르다.

이 사이트로 연습하는 법

  1. 이 강의와 파이썬 도구함을 먼저 읽는다.
  2. 알고리즘 강의를 읽고 연결된 문제를 푼다. 막히면 문제 화면의 힌트 탭을 한 단계씩 열어 본다.
  3. 맞힌 뒤에는 모범 답안 탭과 비교하고, 시간이 얼마나 걸렸는지 본다.
  4. 시험 모드로 4시간 동안 여러 문제를 연달아 풀어 본다.
