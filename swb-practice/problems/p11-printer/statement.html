문제 설명

사무실에 프린터가 N대 있고, 0번부터 N-1번까지 번호가 붙어 있다. 프린터는 한 번에 작업 하나만 처리하고, 1초에 1페이지를 인쇄한다. 즉 P페이지짜리 작업은 시작한 시각부터 정확히 P초 뒤에 끝난다.

작업이 들어오면 다음 규칙으로 처리한다.

  1. 놀고 있는 프린터가 있으면 번호가 가장 작은 프린터가 바로 시작한다.
  2. 모든 프린터가 일하는 중이면 대기열의 맨 뒤에 선다.
  3. 프린터가 작업을 끝내면, 대기열의 맨 앞 작업이 그 시각에 바로 그 프린터에서 시작한다. 대기열이 비어 있으면 프린터는 논다.

시각 T에 작업이 끝나는 프린터가 여러 대이면 번호가 작은 프린터부터 대기열의 작업을 가져간다.

모든 함수는 시각이 줄어들지 않는 순서로 호출된다 (같은 시각에 여러 번 호출될 수 있다). 시각 T에 호출될 때는 시각 T 이하에 끝나는 작업이 모두 처리된 뒤의 상태를 기준으로 한다. 예를 들어 시각 T에 프린터 하나가 작업을 끝냈다면, 시각 T에 들어온 작업은 그 프린터가 놀고 있는 것으로 보고 처리한다.

구현할 함수

def init(N: int) -> None

각 테스트 케이스의 처음에 호출된다. 프린터는 N대이고, 모두 놀고 있다.

def submit(mTime: int, mJobId: int, mPages: int) -> int

시각 mTime에 mPages페이지짜리 작업 mJobId가 들어온다. 바로 시작하면 그 프린터의 번호를, 대기열에 서면 -1을 반환한다.

def done(mTime: int) -> int

시각 mTime까지(이때 끝나는 작업 포함) 인쇄를 끝낸 작업의 총 개수를 반환한다.

def waiting(mTime: int) -> int

시각 mTime에 대기열에서 기다리는 작업의 개수를 반환한다.

제약 사항

  • 1 ≤ N ≤ 50
  • 0 ≤ mTime ≤ 1,000,000, 호출 순서대로 mTime은 줄어들지 않는다.
  • 1 ≤ mPages ≤ 20
  • mJobId는 모두 서로 다르다.
  • 각 테스트 케이스에서 모든 함수를 합쳐 최대 30,000번 호출한다.

예시

프린터 2대

호출반환설명
submit(0, 1, 5)00번 프린터가 시작, 5초에 끝남
submit(1, 2, 3)11번 프린터가 시작, 4초에 끝남
submit(2, 3, 2)-1모두 일하는 중이라 대기
submit(3, 4, 1)-1대기
waiting(3)2작업 3, 4
done(4)1작업 2가 끝남. 작업 3이 4초에 1번 프린터에서 시작해 6초에 끝남
waiting(4)1작업 4만 남음
done(5)2작업 1이 끝남. 작업 4가 5초에 0번 프린터에서 시작해 6초에 끝남
waiting(5)0
done(6)4두 프린터가 6초에 모두 끝남

힌트: mTime이 최대 100만이라서 1초씩 흘려보내는 방식은 호출이 많으면 느리다. "다음에 일이 일어나는 순간"으로 건너뛰는 방법을 생각해 보자.
